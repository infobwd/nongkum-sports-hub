## ข้อขัดแย้งที่ยังไม่แก้เดา

- ผังเปตอง 10 ปีชาย (เมื่อแก้ทีม 2 เป็นเสาหงส์) จะเรียง 1 หนองกระทุ่ม, 2 เสาหงส์, 3 รางขาม, 4 ทุ่งมะสังฯ แต่ **ตารางคู่ 2 ยังเป็น รางขาม – หนองกระทุ่ม**, ขัดกับผัง 3–4. ผู้จัดต้องยืนยันรายชื่อคู่ 2/ตำแหน่งผัง ก่อนแก้ตารางแข่งหรือเผยแพร่เป็นฉบับรับรอง.
- คู่ที่ 9 ของเซปักตะกร้อใน 41 หน้าและ JSON มีอยู่เพียงรายการเดียวแล้ว; ห้ามลบรายการจริงจนเหลือศูนย์.
- ภาคผนวก PDF V3 ที่ฝังใน 155 หน้าใช้เป็นหลักฐานเก่า ต้องคงเดิมหรือใส่ป้ายอ้างอิงฉบับแก้แทนการลบ/เขียนทับหลักฐาน.
- ไม่เพิ่มผลแข่งขัน ผู้ชนะ คะแนน วันเวลา และไม่เปลี่ยนจำนวนรายการ 236 ที่ผู้จัดยืนยัน.

## ขั้นดำเนินงาน

1. เก็บแผนนี้ใน branch แยก **ก่อนแก้เอกสาร**; ตรวจ `main` + PR เปิดและขอบเขตขัดแย้ง.
2. จัดทำ **สำเนา PDF 41/155 หน้าเพื่อให้ตรวจร่าง** พร้อมแก้จุดชัดเจนและบันทึกข้อขัดแย้งที่ยังต้องตรวจ; ไม่เขียนทับ PDF ต้นฉบับ, V2/V3 SHA-pinned, พิกัดไฮไลต์, แอป/ผล/Sheets.
3. หากต้องปรับ JSON ใน PR แยก **ต้องรักษา `source_*` ต้นฉบับ** และใส่ข้อมูลแก้ไขในฟิลด์เสนอ/รับรองที่มีหลักฐาน; ห้ามเปลี่ยน public site ก่อน Merge และ QA.
4. QA PDF นับหน้าคงเดิม (41/155), A4, พิกัดข้อความที่แก้, ไม่มีข้อความทับ/ตกหล่น; ตรวจ 236 รายการและเลขคู่ซ้ำอย่างน้อยรายการกีฬาเกี่ยวข้อง.
5. อัปโหลด **ไฟล์ใหม่เพื่อให้ตรวจร่าง** เข้า Drive โฟลเดอร์สูจิบัตร ตรวจลิงก์และขนาดอีกครั้ง.
6. เปิด PR ให้ผู้จัดตรวจ; **ไม่ Merge/สลับเว็บไซต์จนผู้จัดอนุญาต** และต้องทดสอบ Safari/LINE/Chrome หากจะเผยแพร่จริง.

## R27-B — คำสั่ง 13 พฤศจิกายน 2569: แก้คู่ 2 ให้ตรงผังและปรับฟอนต์

**ผู้จัดสั่ง:** “แก้ไขในตารางให้ตรงกับผัง และ ดูเรื่องฟอนต์ด้วยครับ”

- ตำแหน่งที่ยืนยันจากผัง R27: เปตอง 10 ปีชาย 01 หนองกระทุ่ม, 02 เสาหงส์, 03 รางขาม, 04 ทุ่งมะสังฯ, 05 พุพรหม, 06 วังเขาแก้ว, 07 วังด้ง, 08 หนองกุ่ม.
- **แก้ตารางคู่ที่ 2** จาก `รางขาม – หนองกระทุ่ม` เป็น `รางขาม – ทุ่งมะสังฯ` โดยคงวันที่ 12 พ.ย. 2569 เวลา 09.00 น. สนาม 2, คู่ 1/3/4 เดิม และรอบรองคู่ 10 เป็นผู้ชนะคู่ 3–4 ตาม R27.
- แก้เฉพาะ **ไฟล์ตรวจร่าง R27 ฉบับใหม่**: 41 หน้า ตารางหน้า 17 และคำเตือนหน้า 15; 155 หน้า ตารางหน้า 102 และผังหน้า 69/ข้อความเตือนที่อ้างรายชื่อซ้ำ; ปรับหน้าที่จำเป็นเพื่อให้สอดคล้องกับคู่แข่งขันจริงเท่านั้น โดยไม่เขียนทับฉบับ R27 ที่อัปโหลดแล้ว.
- **ฟอนต์:** ตรวจฟอนต์ฝัง/การแสดงอักษรไทย–วรรณยุกต์ในพื้นที่แก้ ให้เข้ากับข้อความข้างเคียง; **ใช้ text layer ที่ค้นหา/คัดลอกได้** แทนภาพซ้อนจุดที่แก้ใน R27 เมื่อทำได้อย่างปลอดภัย; ถ้าบางจุดยังเป็นภาพต้องแสดงข้อจำกัดตรงไปตรงมา.
- คงเลขหน้า 41/155, กระดาษ A4, 236 รายการแข่งขัน, เวลา/สนามเดิม, ใบผลและคะแนนเดิม, ภาคผนวก V3 ที่เป็นหลักฐานเดิม, SHA-pinned viewers และข้อมูลเว็บใช้งานเดิม; **ไม่แก้ `main`, Sheets, JSON, CSS หรือผู้ชนะ** ในรอบ PDF นี้.
- ตรวจด้วยภาพก่อน/หลังรายหน้า, ข้อความดึงจาก PDF, bounding box, ฟอนต์ฝัง/Thai combining marks, ชุดหน้าไม่เปลี่ยน, Drive metadata ขนาดและตำแหน่ง, QA; อัปโหลดแยกเป็น R27-B review-only และอัปเดต PR #136 ให้ผู้จัดตรวจ; **ไม่ Merge/ไม่สลับเว็บ** จนอนุญาต.

## R27-C — แก้ฟอนต์ผิดรุ่นและเพิ่มการตรวจป้องกัน (คำสั่ง 13 พฤศจิกายน 2569)

**ลำดับก่อนทำ:** บันทึกแผนใน PR #136 และคงสถานะ draft; เป้าหมายเป็น PDF ฉบับตรวจร่างใหม่เท่านั้น ไม่แตะ main/เว็บไซต์/Sheets/ผลกีฬา/จำนวน 236 รายการ.

### ผลวิเคราะห์สาเหตุ

- ข้อความใหม่ของ R27-B ใช้ Waree/Waree-Bold เพื่อแก้ภาพข้อความให้ค้นหาได้ แต่ละจุดไม่ได้กำหนดฟอนต์ตามอักษรภาษาไทย **ที่อยู่ติดกันในแถว/ผังเดียวกัน** จึงต่างจาก Noto-Bold (เล่ม 41 หน้า) และ NotoThai/Noto-Sans-Thai/FormalThai (เล่ม 155 หน้า).
- ตรวจผ่านเฉพาะจำนวนหน้า ความครบของข้อความ การฝังฟอนต์ และภาพที่ไม่เสียหาย; **ไม่ได้มีเงื่อนไขให้ฟอนต์ไทยที่แก้ตรงกับฟอนต์เพื่อนบ้าน** จึงไม่มีการหยุดงานเมื่อใช้ฟอนต์ต่าง.
- บางหน้าใช้ฟอนต์หลายแบบโดยตั้งใจ (เช่นตัวเลข Waree กับอักษรไทย Noto) ห้ามลบ/แทน Waree ทั้งเล่ม; ต้องแก้เฉพาะกรอบข้อความเปลี่ยนตาม R27-B และเก็บหน้าส่วนอื่น.

### แผนงานและเกณฑ์ผ่าน

1. เปิด R27-B 41/155 หน้า เทียบ R27, ตรวจขนาด/ตำแหน่ง/ฟอนต์จริงของข้อความในแถวและหน้าที่แก้ พร้อมระบุกรอบข้อความที่แก้ได้.
2. **Font parity:** แทนที่ข้อความไทยที่เพิ่มด้วย Noto-Bold สำหรับช่อง 41 หน้า, NotoThai / Noto-Sans-Thai สำหรับตารางและผัง 155 หน้า, FormalThai สำหรับตัวเลขอ้างอิงที่ใช้ฟอนต์นั้นจริง. ฟอนต์และขนาดต้องเท่ารูปแบบของแถว; ตรวจการจัดวรรณยุกต์ด้วยภาพจริงและการคัดลอกได้.
3. เปลี่ยนเฉพาะข้อความแก้ไขเดิม 41 หน้า (13,15,17) และ 155 หน้า (61,64,69,100,102,103,138) โดยไม่แตะหน้าอื่น/ไม่เปลี่ยนคู่ 2 ที่รับคำสั่งแล้ว.
4. เพิ่มเครื่องมือ QA ที่รับ PDF ฉบับก่อนแก้และหลังแก้กับสเปกตำแหน่ง เพื่อ **ปฏิเสธฟอนต์ต่างรุ่น** หากข้อความไทยในบริเวณแก้ไขไม่ใช่ฟอนต์ที่กำหนด; ตรวจข้อความจริง, page count, ขนาด, ความผิดปกติของสระ/วรรณยุกต์ และ rendered crop.
5. ออกไฟล์ **R27-C REVIEW ONLY** แยกจาก R27/R27-B, ตรวจ QA และอัปโหลด Drive แล้วบันทึกผลเป็นลิงก์/sha ใน branch เดิม PR #136. ยังไม่ Merge/ไม่สลับเว็บก่อนผู้จัดตรวจรับ.

**ข้อห้าม:** อย่าอ้างว่าแก้ฟอนต์เหมือนต้นฉบับหากแค่ฝังฟอนต์หรือคัดลอกข้อความได้; ต้องตรวจชื่อฟอนต์จริงของข้อความไทยที่แก้ และเปรียบเทียบภาพขยายในแต่ละกรอบ. หากฟอนต์ฝังต้นฉบับไม่สามารถใช้กับตัวอักษรไทยได้อย่างถูกต้อง ให้รายงานข้อจำกัดและไม่ออกฉบับอ้างว่าผ่าน.
