2. ให้ภาพและ meta ชื่อกรีฑาอิง `event_id` และ `division` จาก corrected 236-fixture source เหมือน R38; หาก join ไม่ได้ให้ใช้ข้อความไม่ระบุชื่อรายการและทำ QA flag **ไม่เดา**.

4. ตรวจ create-PR bot gate, เปิด PR แยกก่อน merge, ไม่ใช้ `GITHUB_TOKEN` ในเว็บสาธารณะ. QA รูป / LINE preview ของกีฬาแต่ละประเภทและลิงก์ deep link.

## R39-B — ตารางคะแนนมือถือ
1. ลดหน้ากว้างล้นจอด้วย `min-width:0`, `max-width:100%`, ครอบตาราง; จอเล็กแสดงรายชื่อทีมพร้อมสถิติย่อ (ไม่ซ่อนชื่อทีม) และมีปุ่มดูตารางเต็มแบบ accessible.
2. เมื่อกรองโรงเรียน ให้คงทุกทีมในสายที่มีโรงเรียนนั้น และไฮไลต์ทีม แทนการซ่อนคู่แข่ง.
3. แสดง timestamp แบบวันไทย/เวลา Asia/Bangkok ที่ parse ได้ ไม่แสดง ISO raw; ระบุสถานะ 'ยังไม่จัดอันดับ' และไม่สร้างอันดับ/คะแนนจากกติกาที่ยังไม่รับรอง.
4. QA Safari/Chrome/LINE mobile, R15/R38 standings regression, horizontal scroll, reduced-motion และหน้าจอเล็ก.

## R39-C — ขั้นตอนรูปภาพกิจกรรม
1. ใช้ Google Drive ที่มีอยู่เป็น intake (แยกวัน/กีฬา) ไม่ย้าย/ลบภาพหรือเปลี่ยนสิทธิ์ส่วนตัวอัตโนมัติ.
2. ออกแบบ manifest เฉพาะภาพที่ผู้รับผิดชอบตรวจ/อนุญาตแล้ว: fixture/event ID, display consent, source ID ภายในแบบไม่เผยแพร่, caption ทั่วไป, variant thumb/OG, revision, approver evidence ในพื้นที่ส่วนตัว.
3. ห้ามให้หน้าเว็บสาธารณะอัปโหลดเข้า Drive/Storage โดยใช้รหัส/secret; อัปโหลดผ่าน Drive ที่กำหนดสิทธิ์ไว้ แล้วผู้รับผิดชอบคัดเลือก. ไม่มีการเผยแพร่รูปบุคคล/หลักฐานใบคะแนนโดยอัตโนมัติ.
4. พัฒนา validator + template manifest และแนวทางเผยแพร่ภาพที่อนุมัติ ไม่ผูกกับ public results writer.

## R39-D — ผูกภาพที่อนุญาตกับรายการ

3. แยก optimized mobile thumbnail จาก OG 1200x630; ทดสอบ cache/history/version, PWA และ privacy.
