# R49 — แชร์ตารางอันดับผ่าน LINE พร้อมข้อความครบและลิงก์สั้น (17 พ.ย. 2569)

## คำขอผู้จัด
ผู้จัดอนุญาตให้พัฒนาและ Merge: แชร์ตารางอันดับเหมือนแชร์ผลหลายคู่, มีทั้ง “แชร์ตารางนี้” รายสาย และ “แชร์ตารางที่เลือกทั้งหมด”, อ่านคะแนนและอันดับใน LINE โดยไม่จำเป็นต้องเข้าเว็บ และมีลิงก์สั้นกลับเข้าแอป

## ตรวจของเดิมบน main ก่อนแก้
- R48/PR #176 จัดอันดับ **ชั่วคราว** ฟุตบอล 12 ปีชายและฟุตซอล 10 ปีชายสาย A/B จากผลผ่านการรับรอง R32 ตามคะแนน > ผลต่างประตูรวม > ผลพบกันเอง; ข้อมูลที่ยังไม่ครบแสดงอันดับร่วม
- `js/standings.js` อ่านผล R32 ที่อนุญาต, ข้อมูลชุดผลล่าสุดและสำเนาสำรอง, ผัง 236 รายการ, กติกา และมีตัวกรองโรงเรียน/ช่วงชั้น/กีฬา แต่ไม่มีปุ่มแชร์
- `js/shared.js` และ `js/schedule-bulk-share.js` ใช้การแชร์ **ข้อความเต็มรวม URL ในช่อง text เดียว** ด้วย navigator.share, fallback clipboard, dialog และแบ่งตอนเมื่อข้อความยาว
- `t/` เป็นลิงก์สั้นตารางแข่งขัน ต้องไม่เปลี่ยนเส้นทางเก่า; PR ค้างอยู่เป็นงานรูป/PDF/Supabase ไม่แก้ standings หรือ shared ใน main โดยตรง

## ขอบเขตและแนวทาง
1. สร้างตัวสร้างข้อความแชร์แบบ **อ่านอย่างเดียว** แยกจาก engine ตารางคะแนน; รับเฉพาะทีมในสายที่มีอันดับชั่วคราวจากผลที่ผ่านการรับรองจริง หรืออันดับ final จาก snapshot ตรวจสอบแล้ว; ไม่แชร์ตารางไม่มีอันดับ/กีฬาอื่นโดยคาดเดา
2. ข้อความระบุ มิตรภาพเกมส์ 2569, กีฬา/รุ่น/สาย, **อันดับชั่วคราว**, จำนวนผลรับรองจากจำนวนคู่, **ทุกทีม** ในสาย รวมอันดับร่วม, แข่ง/ชนะ/เสมอ/แพ้/แต้ม/ผลต่าง, เกณฑ์ R48, สถานะสำเนาสำรองเมื่อใช้; เวลาเผยแพร่จาก metadata เท่านั้น ไม่สร้างเวลาเอง
3. หน้าตารางมีปุ่มต่อกลุ่ม “แชร์ตารางนี้”, ด้านบนมี “แชร์ตารางที่เลือกทั้งหมด” (แชร์เฉพาะตารางที่จัดอันดับได้และตรงตัวกรอง) พร้อม dialog อ่านตัวอย่าง, เลือกตอน, แชร์ข้อความ LINE ผ่าน native share, คัดลอก, ปิด; รองรับ iPhone/Android/LINE และคีย์บอร์ด
4. ลิงก์สั้นภายในโดเมน **`/o/?c=...`** อ่านรหัสเฉพาะกีฬาและสายหรือชุดตัวกรองที่อนุญาต เปิดกลับ `standings.html` พร้อม group filter และ override โรงเรียนที่จำในเครื่องเพื่อให้ผู้รับเห็นตารางตรงที่แชร์; คง `t/` และ deep links เก่า
5. ตัดข้อความหลายตอน **โดยไม่ตัดกลางตาราง**, ลิงก์ท้ายทุกตอน; ไม่แชร์ข้อมูลบุคคล/คะแนนที่ยังไม่รับรอง ไม่สร้างผู้เข้ารอบหรือสถานะผลทางการ
6. ยังคงการทำงานเดิมของ PWA, ตัวกรอง, โหลดผล 60 วินาที, แหล่งผล R32, GitHub Pages, และกีฬาอื่นโดยไม่เปลี่ยน JSON/DB/คะแนน

## QA และเกณฑ์ปล่อย
- ทดสอบด้วยข้อมูล **จำลองเฉพาะใน QA**: 8 โรงเรียน, football/futsal A/B, อันดับร่วม, คะแนน, ผลต่าง, ไม่เอารอบน็อกเอาต์/ผลร่าง, ซ่อนแชร์กลุ่มยังไม่มีผล, ตัวกรอง, link encode/decode/invalid/legacy, สำเนาและเวลา, แบ่งตอนครบ, native share/cancel/clipboard และ HTML มือถือ
- รัน test ใหม่พร้อม R15-A/R15-B/C/R38/R39/R48, R47 schedule link, GitHub Actions และตรวจ conflict กับ main ก่อน Merge
- หลัง Merge ตรวจ GitHub Pages **รุ่นสคริปต์และตัว redirect จริง**, ทดสอบการแสดงตารางจริงถ้าเครื่องมือรองรับ, แยกสถานะการส่งผ่าน LINE บนเครื่องจริงว่า “ยังไม่ตรวจรับ” หากไม่สามารถทดสอบได้

## สถานะ
วางแผนแล้ว; รอการพัฒนาและ QA; ผู้จัดอนุญาต Merge เมื่อ QA ผ่าน แต่ไม่ถือว่า Merge เท่ากับการตรวจรับจริง

## R49-B — ตรวจรับหน้าเว็บและการมองเห็นลิงก์ (หลัง PR #177)
- PR #177 ผ่าน Actions ทั้ง 10 ชุดและ Merge แล้ว. ตรวจ GitHub Pages พบ `standings.html` ใหม่, กล่องแชร์ และ `/o/?c=f` redirect ใช้งานจริง
- เปิดตารางฟุตบอลผ่านเบราว์เซอร์จริง: มีผลรับรอง 6/15 คู่, ปุ่มแชร์ใช้งานได้, กล่องแสดงข้อมูลทั้ง 6 ทีมครบ
- ข้อสังเกตการใช้งาน: ลิงก์สั้นถูกแนบอยู่ **ท้ายข้อความ textarea** ตามที่ชุดทดสอบยืนยัน แต่ผู้ตรวจไม่เห็น URL ในบริเวณตัวอย่างที่แสดงครั้งแรก จึงตรวจรับการมองเห็น URL ไม่ผ่าน แม้ลิงก์ทำงานจริง
- แก้เฉพาะการแสดง **ลิงก์สั้นแบบคลิกได้ใต้ช่องตัวอย่าง**, คงลิงก์ท้ายข้อความที่ส่ง LINE เหมือนเดิม เพื่อช่วยครูตรวจปลายทางก่อนส่ง
- เพิ่ม QA ดู `href` ของลิงก์ใน dialog ให้ตรงกับในข้อความ, ชัดเจนบนมือถือ; ทดสอบ R49 และ regression ก่อน Merge ภายใต้คำอนุญาตผู้จัดเดิม
- ไม่เปลี่ยนการจัดอันดับ, ผลรับรอง, กติกา, R32/R33, ชุดแชร์เก่า หรือคีย์ลับ; ตรวจหน้าเว็บสาธารณะและสถานะตรวจรับจริงอีกครั้ง
