# R16 — ตารางแข่งขันตามวันที่–เวลา และพื้นที่เลื่อนท้ายหน้ามือถือ

วันที่: 5 พฤศจิกายน 2569 · Scope: presentation + regression only (ไม่แก้ JSON ต้นฉบับและไม่แก้ผลแข่งขัน)

## พฤติกรรมหลังแก้
- กรองรายการก่อน แล้วเรียงทั้งหมดด้วย `js/schedule-order.js` ตามวัน → เวลา → ลำดับกีฬา → รุ่น → เลขคู่/ID
- ใช้วันที่ `planning_date` เฉพาะเมื่อ `planning_date_confirmation=confirmed`; มิฉะนั้นใช้ `source_pdf.source_date_iso` ที่ตรวจรูปแบบและวันตามปฏิทินแล้ว
- ปี 2568 ที่ผิดปกติ 3 แถวไม่มีการคาดเดาแก้เป็น 2569: จัดท้ายในกลุ่มรอยืนยันวันแข่งขัน และการ์ดแสดงคำเตือน
- แสดงหัววันก่อนการ์ด ขณะที่แต่ละการ์ดแสดงชนิดกีฬาและรุ่นไว้เสมอ (เพราะเลิกจัดกลุ่มกีฬา)
- คง `limit=12` และปุ่มแสดงเพิ่มทีละ 12 โดยเรียงก่อนตัดรายการ ไม่เปลี่ยนการ์ดเดิม แชร์ LINE, PDF page/deep link, scorecard, filter หรือ route
- แถบสองเมนูล่างคง fixed แต่ `navigation.js` ใช้ ResizeObserver วัดความสูงจริงและตั้ง `--mobile-nav-occupied`; CSS เว้นพื้นที่ท้าย document พร้อม safe-area fallback โดยไม่มี fixed mask ใหม่

## Regression อัตโนมัติ
`node scripts/ux/test-schedule-chronological-r16.mjs` รวมใน workflow R14 เดิม:
- รายการ 237 ครบ ID ไม่ซ้ำ แหล่งต้นฉบับไม่ถูกเปลี่ยน
- วัน 7 วันตามลำดับ, 3 ปีผิดปกติในกลุ่มท้าย
- เวลาในวันเดียวกันขึ้นตามเวลา (เวลาว่างท้ายวัน)
- 12→24 รายการรักษาลำดับ; วันอาจต่อเนื่องข้ามจุดกดโหลดเพิ่ม
- วันที่ override เฉพาะกรณียืนยัน; invalid ISO ไม่ถูกใช้
- ตรวจสัญญาเมนูล่าง, ลิงก์ PDF, แชร์, และ approved-only results

## ตรวจรับบนอุปกรณ์จริงหลัง deploy
1. iPhone Safari, PWA และ LINE in-app browser: เลื่อนจนเห็นข้อความทั้งหมดของ “สำหรับผู้จัดการแข่งขัน · ข้อมูลตรวจรับ P2” และ footer ได้ ไม่ถูกเมนูล่างบัง
2. เปิด/ปิด disclosure ข้อมูล P2 แล้วเลื่อนไปถึงลิงก์สุดท้ายโดยแตะได้; ทดลองแนวตั้ง/แนวนอนและขนาดตัวอักษรใหญ่
3. ตรวจวันที่ 12, 13, 16–20 พ.ย. 2569 ตามลำดับ และ 3 รายการรอยืนยันท้ายรายการ หลังคลิกแสดงเพิ่มจนสุด
4. กรองโรงเรียนวังด้ง, ฟุตบอล, ช่วงชั้น; แสดงเพิ่ม 12 รายการแล้วตรวจเวลาและการเลื่อน
5. แชร์คู่ผ่าน LINE, เปิดสูจิบัตรหน้า 7 และกลับสู่คู่เดิม; ตรวจลิงก์สั้นเก่าไม่เปลี่ยน
6. หน้าผลการแข่งขันยังแสดงเฉพาะผลรับรอง (ขณะนี้ public JSON ยังว่าง) และเมนูล่างใช้งานได้ด้วยการแตะครั้งเดียว

หมายเหตุ: Regression ใน CI ไม่ใช่การยืนยันทางสายตาบนอุปกรณ์จริง ให้ตรวจ QA ข้อ 1–6 เพิ่มบน host ก่อนประกาศใช้งานอย่างเป็นทางการ
