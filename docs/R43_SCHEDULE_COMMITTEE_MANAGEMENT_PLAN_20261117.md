## หลักการป้องกันข้อมูล
1. แยกสถานะ **ร่าง / เสนอแก้ / ตรวจรับ / เผยแพร่ / ยกเลิก** และสถานะยืนยันย่อย: คู่แข่งขัน วัน เวลา สนาม และผัง
2. รักษา `fixture_id` เดิมสำหรับคู่เดิม, ไม่แตะข้อมูลผลรับรอง R32; หากมีผลรับรองแล้วต้องระงับคำขอเปลี่ยนคู่/กีฬา/รุ่นจนกว่าจะผ่านการตรวจผลกระทบ
3. กรรมการ: ระดับ `sport`, `division`, `fixture` และ role; หนึ่งบุคคลอาจหลายหน้าที่; `person_id`/school_id จากทะเบียนส่วนตัว ไม่จับคู่ด้วยชื่ออย่างเดียว; ตรวจเวลาทับซ้อนก่อนเผยแพร่
4. ข้อมูลชื่อกรรมการที่ไม่รับรอง **ไม่ออก public JSON**, ประวัติการแก้ชื่อและข้อมูลส่วนตัวอยู่เฉพาะพื้นที่มีสิทธิ์
5. ต้นฉบับ PDF/JSON ไม่เขียนทับ. ร่างการแก้ต้องมี `base_source_key`, `base_revision`, ผู้เสนอ, เหตุผล, เวลาบันทึก; อนุมัติพร้อม audit และเผยแพร่รุ่นใหม่เท่านั้น
6. Supabase เป็นพื้นที่ข้อมูลปฏิบัติงานเมื่อระบบปลอดภัยพร้อม, แต่ `main` GitHub เป็นหลักฐานของไฟล์สำรองเผยแพร่. ต้องมี atomic publish + ตรวจ SHA/source version สองทาง ห้ามเลือกข้อมูลไม่ตรงกันเอง
7. แยกสิทธิ์ผู้จัดตาราง/ผู้มอบหมายกรรมการ/ผู้รับรอง, backend ตรวจทุกคำขอ, ไม่ฝัง secret หรือ service role ลง GitHub Pages, ใช้ RLS + Edge Function/การรับรองบนเซิร์ฟเวอร์ (ห้าม direct writes จาก browser)

## ระยะพัฒนา
### R43-A — พื้นฐาน/ตรวจร่าง (สาขานี้)
- หน้าทำงาน `schedule-manager.html` บนมือถือ: ค้นหาจาก fixture ID / กีฬา / โรงเรียน / วัน และเลือกจาก 236 รายการ
- แก้ไขวัน เวลา สนามและหมายเหตุใน **ร่างส่วนตัวที่ไม่เผยแพร่**, เพิ่มบันทึกมอบหมายกรรมการรายรายการในร่าง (ไม่อ้างว่าแต่งตั้งจริง)
- ตรวจรูปแบบวัน/เวลา, ชื่อซ้ำ/ช่วงเวลาทับซ้อนเบื้องต้น, ห้ามเปลี่ยนคู่ที่มีผลรับรองผ่านหน้าเตรียมแก้
- ส่งออกคำขอแก้เป็น JSON เฉพาะในเครื่องสำหรับผู้จัดนำไปตรวจส่วนตัว, ไม่ส่งข้อมูลกรรมการร่างขึ้น Repo/GitHub Pages, ไม่เก็บรายชื่อใน localStorage; ล้างหลังปิด/รีเฟรช
- ลิงก์ทางเข้าในเมนู `เพิ่มเติม` และลิงก์เจาะรายการจากการ์ดที่แยกจากปุ่ม R34; ป้ายใน UI ชัดว่า “เตรียมคำขอแก้ไข · ยังไม่บันทึกขึ้นระบบ”
- ทดสอบ unit/static + browser/mobile synthetic 320/375/390/430px; ไม่เรียก API เขียนจริง

### R43-B — รับคำขอแก้ไขอย่างปลอดภัย (PR ถัดไป / ยังไม่เปิดใช้)
- DB private staging: `schedule_change_requests`, `schedule_change_audit`, `committee_assignment_requests`, `committee_assignment_audit` ผูก source_key/fixture_id/version
- ตั้งสิทธิ์ใหม่สำหรับผู้จัดตาราง (ไม่ใช้ R34/R37), จำกัดอัตราลองรหัส, revocable sessions, แยกเสนอ/รับรอง, ตรวจสัญญา RLS/Edge โดยทีมดูแล
- ข้อมูลกรรมการใน private teacher directory เท่านั้น ไม่สรุป identity จากสตริงในร่าง PDF

### R43-C — ปฏิบัติงาน/ตรวจทับซ้อน
- สืบทอดมอบหมายระดับกีฬา → รุ่น → รายคู่พร้อม override; ตรวจหน้าที่หลายสนามพร้อมกัน, เวลาต่อเนื่องและการเปลี่ยนสนาม
- คิวตรวจและอนุมัติทีละส่วน, conflict badges, เหตุผลเปลี่ยนหลังมีผลรับรอง

### R43-D — ประกาศรุ่นข้อมูล/ซิงก์
- เผยแพร่ approved schedule projection แบบ atomic, อัปเดต R33 `active` และ GitHub snapshot/เว็บไซต์ด้วย compare+QA, คงเวอร์ชันเก่าและหลักฐาน; หน้าแสดงผลแยก draft/confirmed ไม่ใช้ประวัติเดาผู้ชนะ
- ปรับสูจิบัตรเมื่อข้อมูลได้รับรอง; จัดการผังและผล R32 แยกตามหลักฐาน, ป้องกัน cache/PWA ไม่ทำให้ผู้ใช้เห็นปนรุ่น

### R43-E — ตรวจรับสนามจริง
- ทดสอบ Safari iPhone, Android Chrome, LINE, PWA online/offline และสิทธิ์ผู้ใช้จริง; ทดสอบไม่ทับปุ่ม R34/ลิงก์ PDF; ขอการตรวจรับจากผู้จัด
