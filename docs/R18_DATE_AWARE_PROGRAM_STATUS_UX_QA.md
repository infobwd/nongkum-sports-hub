# R18 — หน้าตารางแข่งตามวันปัจจุบัน พร้อมข้อความสถานะที่ไม่ชวนเข้าใจผิด

วันที่ 5 พฤศจิกายน 2569 · ต่อจาก PR #38 (R16) และ PR #40 (R17)

## พฤติกรรมหน้าตาราง

- หน้าตารางเริ่มต้นที่โหมด **วันนี้ / วันแข่งขันถัดไป** โดยใช้เวลาประเทศไทย `Asia/Bangkok` ไม่อิง timezone โทรศัพท์ และแสดงรายการ **ทั้งวัน** (ไม่ตัดรายการที่เวลาเริ่มผ่านไปแล้ว)
- ก่อนวันแข่งขันแรก: แสดงวันแรกที่ยังมาไม่ถึง; ระหว่างวันแข่งขัน: แสดงวันนั้น; เมื่อไม่มีวันใดในอนาคตภายใต้ตัวกรอง: แสดง **ทุกวันรวมย้อนหลัง** พร้อมชี้แจงแทนหน้าว่าง
- สลับ **ทุกวัน** เพื่อดูทั้ง 237 รายการรวมวันเก่าและ 3 รายการที่รอยืนยันปี ไม่ตัดข้อมูลหรือเปลี่ยน JSON; เมื่อกลับจากแท็บผลแข่งขันในแท็บเบราว์เซอร์เดิม จะจำโหมดที่ผู้ใช้เลือกโดย `sessionStorage` เฉพาะการกลับหน้า ไม่ทำให้การเปิดหน้าใหม่เสียค่าเริ่มต้นที่เน้นวันนี้
- สลับตัวกรองโรงเรียน กีฬา ช่วงชั้น หรือคำค้น → กรองก่อนเลือกวันถัดไปของตัวกรองนั้น; เรียงวันที่และเวลาภายในวัน; โหลดเพิ่ม 12 รายการเฉพาะชุดที่กำลังมอง
- คงพฤติกรรม R17 `from=results#programListing` เลื่อนมาหัวโปรแกรมและลบ marker, คง PDF page deep link, LINE share, โปรแกรมกรีฑา, หน้าผลรับรอง และการคืนจากหน้า PDF

## ข้อความสถานะ

- **ยืนยันวัน เวลา สถานที่แล้ว 24 คู่ (เปตอง 12–13 พ.ย. 2569)**: แสดงป้ายยืนยันที่การ์ด แต่ไม่แสดง QA warning หรือหมายเหตุตรวจ PDF ต่อผู้ชมทั่วไปที่สับสนว่า *กำหนดแข่ง* ยังไม่ยืนยัน; หลักฐาน QA อยู่ในไฟล์ JSON เดิมและหน้าตรวจรับ
- อีก 213 รายการยังอยู่ระหว่างตรวจรับ **แยกความหมายจากผลการแข่งขัน** และไม่เรียกทุกคู่บนหน้าเว็บว่าได้รับการรับรองแล้ว
- เปลี่ยนคำ “ข้อมูลร่าง” ที่หัวเว็บ การ์ดรายละเอียด จำนวนรายการ สถานะรีเฟรช และท้ายหน้า ให้เป็นคำกลาง “ตารางการแข่งขัน” หรือสถานะตรวจรับตามจริง; ไม่เปลี่ยน `metadata.all_data_approved=false`, `status: draft`, `review_status: draft`, หรือความหมายของผลรับรอง
- ลิงก์แชร์สั้นเก่าและเอกสารเจ้าหน้าที่ยังเก็บ provenance เดิม จึงไม่ทำลาย OG ที่เคยเผยแพร่หรือระบบตรวจย้อนกลับ

## Regression / การตรวจรับ

`node scripts/ux/test-date-aware-program-r18.mjs` ทดสอบ:
1. เวลา UTC ข้ามวันเป็นวันไทย และสถานะก่อนแข่ง/วันนี้/หลังหมดฤดูกาล
2. กรองแล้วเลือกวันของรายการที่เหลือ; ไม่ซ่อนรายการเก่าเมื่อไม่มีวันใกล้เข้ามา
3. โหมดแสดง 12 รายการใกล้ที่สุด ↔ ทุกวันและโหลดเพิ่มเป็น 24 รายการ
4. การจำโหมดเดิมเมื่อกลับจากผลแข่งขันโดยไม่เปลี่ยนการเปิดหน้าใหม่
5. ยืนยัน 24 รายการตรง JSON, ไม่แสดงคำเตือน PDF ให้คู่ที่ยืนยันแล้ว, เก็บ QA และผลแข่งขันเป็น approved-only
6. รัน R16/R17 และ suite เดิมผ่าน Actions เดียวกัน

ทดสอบผู้ใช้จริงหลัง GitHub Pages deploy: บน iPhone Safari และ LINE เปิดตาราง, สลับโหมด, กรองโรงเรียน, เปิด PDF แล้วกลับ, ไปผลแข่งขันและกลับหน้าตาราง, ทดสอบช่วงวันที่ 12–13 พ.ย. และการ์ดที่ต้องตรวจรับโดยไม่ชี้ว่าผลได้รับอนุมัติ ทั้งนี้ CI ไม่ใช่การตรวจสายตาบนอุปกรณ์จริง.
