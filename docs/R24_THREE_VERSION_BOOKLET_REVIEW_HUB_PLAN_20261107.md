## 3. ประสบการณ์ใช้งานบนเว็บ (มือถือเป็นหลัก)

### A. ทางเข้าจากหน้าตารางแข่งขัน
- ในเมนู **“เพิ่มเติม”** ที่มีอยู่แล้ว เพิ่มหัวข้อ **“เอกสารสูจิบัตรสำหรับตรวจสอบ”** (ไม่เพิ่มปุ่มเต็มหน้าหลายปุ่มบนตาราง)
- มีรายการเอกสารสามใบ: **ตารางแข่งขัน V2 (41 หน้า)**, **รายชื่อกรรมการ V3 (64 หน้า)**, **สูจิบัตรฉบับรวม V4.2-I10 (155 หน้า · ฉบับตรวจร่าง)** พร้อมสถานะฉบับ/แก้ไขล่าสุดที่ตรวจสอบได้จริง
- คงลิงก์ PDF เดิมและการไฮไลท์ V2/V3 ไว้เหมือนเดิม; เอกสาร V4.2 ใช้ลิงก์ตรวจร่างแยก ไม่แทนค่า default โดยอัตโนมัติ

### B. เปรียบเทียบรายการเดียวกัน (เริ่มหลังตรวจ mapping)
- เมื่อกดคู่แข่งขันจากตาราง ให้เลือก **เปิดใน V2** (พิกัด 41 หน้าเดิม) หรือ **เปิดใน V4.2-I10** (หน้าของเล่มรวมที่ตรวจแล้ว); จากหน้ากรรมการให้เลือก **V3** หรือ **V4.2-I10** ในลักษณะเดียวกัน
- ยึด `fixture.id` / `committee source row id` เป็นกุญแจเชื่อม ไม่ใช้เลขคู่/ชื่อคนอย่างเดียว เพราะเลขที่ซ้ำและชื่อบุคคลซ้ำได้
- แสดงผลแยก `MATCHED`, `DIFFERENT`, `NEEDS_REVIEW`, `UNAVAILABLE` จากหลักฐานและฉบับที่เทียบ; ไม่แสดงความสอดคล้องว่าเป็น "ผ่านอนุมัติ"
- หาก page map หาย, ไม่ตรง SHA, รายการถูกตัด, PDF inaccessible, token/rect ไม่ตรง ให้ **เปิดหน้าเอกสารอย่างปลอดภัยหรือแจ้งผู้ใช้** ไม่ไฮไลท์ผิดและไม่เดาตำแหน่ง
- บนคอมพิวเตอร์อาจมีเทียบสองฉบับเคียงกัน แต่บนมือถือใช้แท็บ/ตัวเลือกฉบับทีละเล่มเพื่อให้ LINE WebView ไม่ค้าง; คงปุ่มกลับไปการ์ดเดิม, ตัวเลือกวันที่, ประวัติการแชร์ LINE และท่าทางซูม/ปัดเดิม

### C. การยืนยันข้อมูล (คนละส่วนกับการดูเอกสาร)
- สถานะ `DRAFT` / `UNDER_REVIEW` / `ORGANIZER_CONFIRMED` / `PUBLISHED` ต้องมีแหล่งมติ/วันเวลา/ผู้รับผิดชอบ ไม่ปรับอัตโนมัติจากการที่ข้อความสองฉบับตรงกัน
- ระยะแรกเป็น **read-only review** และสามารถคัดลอกข้อความแจ้งจุดผิดตาม workflow เดิม ไม่สร้างแบบฟอร์มลงคะแนน/แก้ไขข้อมูลแข่งขันใหม่
- หากต่อยอดบันทึกตรวจรับรายโรงเรียน ให้ใช้สิทธิ์ SMIS/ระบบ private ที่มีอยู่ กำหนดผู้ยืนยันและ audit trail ก่อนเปิดใช้งาน; ไม่ปล่อย PII กรรมการ/นักกีฬาใน GitHub สาธารณะ

## 4. สถาปัตยกรรมและหลักฐานเอกสาร (Version Contract)

เสนอจัดทำ registry แยกจากข้อมูลแข่งขัน เช่น `data/booklet-versions.json` (ชื่อไฟล์ตามอนุมัติก่อนพัฒนา) สำหรับแต่ละฉบับเก็บ:
`version_id`, `display_name`, `purpose`, `page_count`, `source_kind`, `pdf_revision_sha256`, `document_status`, `access_mode`, `viewer_route`, `coordinate_map_revision`, `approved_at` (null เมื่อยังไม่รับรอง)

- อย่าพิมพ์ว่า public หรือเปิด download สาธารณะจาก Google Drive จนตรวจ permission/สิทธิ์ภาพบุคคลของเล่ม 155 หน้าและมติผู้จัด; หาก Drive เป็น private ให้แสดง "เปิดเอกสารสำหรับผู้มีสิทธิ์" และทางเลือกขอเข้าถึงอย่างเหมาะสม
- พิกัดต้องผูก **version + sha + page + record ID + rect**. ตรวจไฟล์จริงก่อนใช้. SHA ของ V2/V3 แตกต่างจาก 155 หน้าและไม่สามารถ reuse พิกัดเดิม
- PDF 155 หน้าอาจมีข้อมูลที่ยังขัดแย้ง 6 กลุ่มผังและประเด็น R11E ที่รอรับรอง ห้ามสร้างผลการแข่งขัน/อันดับ/กำหนดการใหม่
