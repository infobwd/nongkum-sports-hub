# R22 — หน้า review.html: ปุ่มขึ้นบนและดึงลงเพื่ออัปเดต

วันที่ 6 พฤศจิกายน 2569 | ขอบเขต: การนำทาง/อัปเดตหน้าตรวจสูจิบัตร

## สถานะเดิม
- `review.html` มีปุ่ม `#reviewRefresh` และ `js/review.js` มี `load()` แบบ no-store แล้ว แต่ยังไม่เชื่อม `window.NongkumPageRefresh`
- หน้าโปรแกรม/ผล/อันดับเรียกใช้ `css/back-to-top.css`, `css/pull-refresh.css`, `js/back-to-top.js`, `js/pull-refresh.js`; `review.html` ยังไม่ติดตั้ง
- `review.html` เปิด PDF ด้วย `#pdfPreview` และมีสถานะ `body.review-pdf-open`: มือถือ/แท็บเล็ตเป็น dialog; เดสก์ท็อปความกว้างเกิน 1000px เป็นพื้นที่อ่าน PDF คู่กับรายการที่เลื่อนแยกใน `#reviewMain`

## แผนแก้
1. เพิ่มไฟล์ CSS/JS ร่วมของสองฟังก์ชันใน `review.html` โดย **ไม่ทำสำเนาอีกระบบ**
2. ต่อ `NongkumPageRefresh` เข้ากับ `load()` เดิม ให้คืนค่า `true/false` ตามความสำเร็จเพื่อให้ข้อความแจ้งผลถูกต้อง; ห้ามโหลดซ้ำระหว่างคำขอ; คงตัวกรอง/การนำทาง/อ่าน PDF เดิม
3. ใน shared pull-refresh ห้ามทำงานเมื่อ `body.review-pdf-open` และไม่ดึงถ้าสัมผัสที่ controls/โมดัล; อนุญาตเมื่ออยู่ด้านบนและดึงลงแนวตั้งเท่านั้น
4. ใน shared back-to-top: หน้า review ปกติใช้การเลื่อนหน้าแบบเดิม; เมื่อเปิด PDF แบบสองคอลัมน์บนเดสก์ท็อป ให้ตรวจ/เลื่อน `#reviewMain` แทน `window`, วางปุ่มที่คอลัมน์รายการ; เมื่อเปิด PDF แบบ modal ในมือถือซ่อนปุ่มจนปิด PDF
5. เปลี่ยนปุ่ม “รีเฟรช” เป็น “อัปเดต” รวมทั้งคำแจ้งความสำเร็จ/ผิดพลาดที่เหมาะกับครู; ไม่เปลี่ยนสถานะ “ยังไม่รับรอง” ของเอกสาร
6. เพิ่ม regression test ครอบคลุมการมี asset, callback, desktop independent scroll, mobile modal, gesture guard, duplicate-load; เพิ่มเข้า CI และตรวจชุดทดสอบเดิม

## จำกัดความเสี่ยง
- ไม่แก้เอกสาร PDF, `pdf-viewer.html`, JSON, การจัดอันดับ, ข้อมูลกรรมการ หรือการอนุมัติ
- ไม่เพิ่ม fixed overlay ทับหน้าตรวจเอกสาร; ปุ่มควรอยู่เหนือ mobile navigation/safe area เสมอ
- หากมี PR แก้ไฟล์ซ้ำ ต้องตรวจความเปลี่ยนแปลงบน main ก่อน merge; merge ไม่เท่ากับผ่านการทดสอบมือถือจริง

## ตรวจรับ
- หน้า review ไม่มี PDF: เลื่อนเกิน 300px จึงเห็นปุ่ม; กดแล้วกลับบนสุด; ดึงลงจากบนสุดเรียกโหลดฉบับล่าสุด
- เมื่อโหลดไม่สำเร็จ รายการเดิมยังแสดงและแจ้งเหตุผลอย่างสุภาพ
- เมื่อเปิด PDF เดสก์ท็อป: ปุ่มเลื่อนเฉพาะรายการทางซ้าย ไม่เลื่อนหน้า PDF ทางขวา
- เมื่อเปิด PDF มือถือ: ปุ่มขึ้นบน/gesture ของหน้าหลักไม่รบกวนการเลื่อนและขยาย PDF; เมื่อปิดกลับมาทำงานได้
- ลิงก์จากตารางแข่ง, หน้าตรวจ, ปุ่มเปิด PDF และตัวกรองยังทำงานเหมือนเดิม
