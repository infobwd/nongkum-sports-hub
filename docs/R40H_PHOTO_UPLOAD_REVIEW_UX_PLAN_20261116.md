# R40-H — ลดขั้นตอนส่งภาพและตรวจอนุมัติบนมือถือ (16 พฤศจิกายน 2569)

## สถานะ
แผนพัฒนา **แยกสาขา** จาก R40-G ที่ Merge แล้ว (PR #164); ยังไม่ Merge/เผยแพร่/ตรวจรับ จนกว่าจะมีหลักฐาน QA และอนุญาตจากผู้จัด

## หลักฐานและปัญหาที่ตรวจพบ
- iPhone Safari ภาพหน้าจอจริง 6 ภาพ: ช่องรายการแข่งขันชื่อยาวล้นจอ; ส่งแล้วมีเพียงข้อความสถานะอยู่ใต้ฟอร์มและเคลียร์ภาพ จึงสับสนว่าส่งถึงผู้ตรวจหรือไม่
- หน้า review ใช้หัวข้อ 'ภาพที่รอตรวจ' แม้การ์ดเป็น 'เผยแพร่แล้ว'; ช่องสิทธิ์ 2 ช่อง/หลักฐาน/confirm หลายขั้น; ข้อผิดพลาดเก่าแสดงค้างท้ายฟอร์ม
- สถานะจริง R40: `review`, `approved` = อนุญาตใช้ภายใน; สถานะเผยแพร่ R40-G แยกเป็น `private/publishing/failed/published/revoked`; ห้ามยุบสิทธิ์ภายในกับการอนุญาตเผยแพร่เว็บเข้าด้วยกัน
- สำรวจ `main`, PR #159 ที่ยังเปิดและมีไฟล์ซ้ำกับ R40; ไม่ Merge ทับ PR นั้น ไม่แตะ R32/R33/R41 หรือผลรับรอง

## เป้าหมาย / ลำดับพัฒนา
1. **ส่งภาพ 3 ขั้น:** เลือกรายการ > ถ่าย/เลือกภาพ > ส่งภาพ; ซ่อนคำอธิบายเทคนิคที่ไม่จำเป็นในส่วนรายละเอียด; คง WebP 250KB/JPEG fallback และตรวจข้อมูลภาพฝั่ง server
2. **ส่งสำเร็จชัดเจน:** เมื่อ Edge ตอบ `ok:true` เท่านั้น ให้หน้าแสดงแผงใหญ่ 'ส่งภาพสำเร็จแล้ว — รอผู้ตรวจ' ชื่อรายการ, เลขอ้างอิงย่อ และปุ่ม 'ส่งภาพเพิ่ม' กับ 'ดูสถานะภาพที่ส่ง'; ป้องกันส่งซ้ำและระบุ 'ยังยืนยันการส่งไม่ได้' เมื่อเครือข่ายไม่ตอบ; ห้ามอ้างสำเร็จจากแค่กดปุ่ม
3. **ติดตามสถานะของภาพตนเองอย่างจำกัดสิทธิ์:** เพิ่ม service-role-only RPC สำหรับคืน metadata ของภาพที่ผูกกับ editor session hash ที่ยังไม่หมดอายุ (ไม่ใช้แค่ชื่อผู้ส่งหรือ UUID เพื่อเปิดข้อมูลข้ามคน); แสดงสถานะส่งแล้ว/รอตรวจ/อนุญาตใช้ภายใน/เผยแพร่แล้ว/ส่งกลับแก้ไข/ถอนแล้ว ไม่แสดงภาพส่วนตัวหรือชื่อผู้ตรวจ; ไม่รับรองย้อนหลังข้าม session 6 ชม. โดยไม่มีบัญชีส่วนบุคคล
4. **แก้ Select2 iPhone:** จำกัดความกว้าง/ellipsis; แสดงรายละเอียดรายการที่เลือกภายในฟอร์มเป็นข้อความอ่านได้หลายบรรทัด; รองรับกรณี CDN ไม่พร้อมด้วย native search; ไม่แก้รายการตาราง R33
5. **หน้าตรวจภาพ:** ส่วนรอตรวจเด่น; ภาพที่เผยแพร่แล้วและถอนแล้วแยกส่วน; ยืนยันเผยแพร่ด้วย checkbox ที่ชัดและบันทึกหลักฐานอย่างน้อย 8 ตัวอักษร; ปุ่มอนุมัติเผยแพร่เป็นปุ่มหลัก, 'เก็บไว้ภายใน' เป็นทางเลือกรอง; แสดงข้อผิดพลาดใกล้บัตรพร้อมล้างเมื่อแก้; ห้ามเผยแพร่โดยไม่มีสิทธิ์ หรืออาศัย `approved` ภายใน
6. **QA และความปลอดภัย:** automated test Node/Deno/PostgreSQL ที่ครอบคลุม token scope, ไม่มีข้อมูลส่วนตัว, UX success/failure, ปุ่มซ้ำ, iOS overflow, ไร้การเดาผล, R40-G regressions; Chromium mobile synthetic screenshots; ตรวจ Android Chrome/iPhone Safari/LINE จริงหลังอนุญาต Merge และ Deploy
7. **กระบวนการ:** แผนก่อนโค้ด > พัฒนาในสาขานี้ > CI > PR พร้อมหลักฐาน > Merge เมื่อผู้จัดอนุญาต > DB/Edge จาก main > ตรวจเว็บจริง > ตรวจรับโดยผู้จัด

## ข้อจำกัดที่ต้องรักษา
- ห้ามเผยแพร่รูปบุคคล/นักเรียนใน public bucket ก่อนตรวจสิทธิ์เผยแพร่เฉพาะภาพ; `approved` ภายในไม่ใช่ public
- ยืนยันสถานะเฉพาะเมื่อได้ผล server ไม่ใช้การคาดเดา; ป้องกันการส่งซ้ำ/กดซ้ำ
- ไม่เปิด private image ให้ผู้ส่งดูผ่าน API ใหม่; ห้ามใช้เลข ID เพียงอย่างเดียวเป็นสิทธิ์ดูสถานะผู้อื่น
- ไม่นำ token, ชื่อบุคคล หรือหลักฐานสิทธิ์ลง public JSON/GitHub; R32 approved results และ R33 active fixtures ไม่เปลี่ยน
- งานยังไม่เสร็จจน CI ผ่าน มีหลักฐานมือถือจริง และตรวจรับระบบที่ Deploy
