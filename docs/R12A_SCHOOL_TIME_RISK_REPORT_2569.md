## 4. ข้อจำกัดก่อนกรรมการแก้ตาราง

1. **เปตอง 12–13 พฤศจิกายน 2569:** 24 คู่ได้รับการยืนยันเฉพาะวันและสถานที่โรงเรียนบ้านหนองกระทุ่ม; PDF ให้ค่า `draft_time` แต่ **ยังไม่มีเวลาเริ่มรายคู่/คอร์ตที่กรรมการรับรอง**. ใช้รายการนี้เป็นแบบฟอร์มให้กรรมการตรวจเวลาและคอร์ต ไม่ยกระดับเวลา PDF เป็น approved เอง. ตรวจ QA เปตอง 10 ปีชายด้วย
2. **กรีฑา 16 พฤศจิกายนตาม PDF ร่าง:** 50 รายการยังไม่มีเวลาเริ่ม ต้องให้กรรมการกำหนดช่วงเวลา/ระยะเวลารายรายการและเวลาเรียกตัว จึงประเมินความเสี่ยงพร้อมยิงจุดโทษ/เปตองได้
3. **รอบถัดไปที่ยังไม่ทราบทีม:** 60 คู่มีทีมอย่างน้อยหนึ่งฝั่งที่ยังไม่ได้ระบุรหัสโรงเรียน; ต้องติดธง conditional ไม่เดาว่าโรงเรียนใดจะชนะ
4. **3 แถวปี 2568 ที่ค้าง QA:** Candidate ไม่กรอก `draft_date`; ห้ามเปลี่ยนเป็นปี 2569 โดยคาดเดา
5. **ระยะเวลา/สนาม/กรรมการ:** `สนาม 1` คนละกีฬาอาจไม่ใช่สนามเดียวกัน ห้ามสรุปว่าทรัพยากรชนกันจากชื่อสนามซ้ำโดยไม่มี mapping สถานที่จริง
6. **ข้อมูลยังเป็นร่างทั้งหมด:** R12A ไม่เปลี่ยน `data/draft-schedule.json`, `data/public-results.json`, Google Sheets, Google Docs หรือหน้าแชร์ LINE

## 5. รหัสที่พัฒนาแล้วและวิธีทดสอบ

- [ตัวคัดกรอง](../scripts/r12/screen-draft-risk.mjs) แยกรายการเวลาเริ่มตรงกันและใกล้กัน พร้อมส่งออก JSON ที่ไม่มีข้อมูลส่วนบุคคล
- [ทดสอบกรณีสมมติ](../scripts/r12/test-screen-draft-risk.mjs) ตรวจกรณีวันเดียวกัน, ช่วงห่าง 30 นาที, ทีมซ้ำในคู่เดียว, วันผิด, ข้อมูลไม่ครบ, รหัส fixture ซ้ำ
- [GitHub Actions](../.github/workflows/r12a-school-time-risk.yml) ตรวจทั้ง synthetic tests และ deterministic report เทียบ source candidate โดยไม่เขียนข้อมูลใน CI
- รันใน root repo:
```bash
node scripts/r12/test-screen-draft-risk.mjs
node scripts/r12/screen-draft-risk.mjs --check
# เมื่อต้นฉบับเปลี่ยน revision และผ่านการตรวจ ให้สร้าง snapshot ใหม่โดยเจตนา:
node scripts/r12/screen-draft-risk.mjs --write
```

**กฎยืนยัน:** หากข้อมูลต้นฉบับเปลี่ยนแล้ว `--check` ไม่ผ่าน ให้ดู diff/เหตุผลก่อนเปลี่ยน snapshot ไม่แก้ค่าคาดหวังให้ผ่านโดยไม่มีการตรวจ
