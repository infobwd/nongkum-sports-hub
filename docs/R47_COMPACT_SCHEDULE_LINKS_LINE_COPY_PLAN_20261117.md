## เป้าหมาย
1. ลิงก์สั้นลงกว่าระบบ `/t/?s=wangdong&d=261118&r=a` เป็น `/t/?c=<รหัสสั้น>` ภายใต้โดเมน GitHub Pages เดิม โดยไม่พึ่ง TinyURL/Bitly และรักษาลิงก์ `/t/?s=...` เดิมทุกลิงก์
2. รหัสใช้ deterministic reversible codec เวอร์ชันเพื่อเก็บโรงเรียน (8), กีฬา (9), ช่วงชั้น (3), วัน/ทุกวัน/ไม่ระบุ, โหมดผล และป้องกันรหัสเสีย/ไม่รู้จัก; กรณีกรองด้วยข้อความค้นอิสระ fallback ลิงก์เดิมเพื่อไม่เสียตัวกรอง
3. LINE ตัด `(ยืนยันแล้ว)` หลังสนามหลัก; ตัด `(รอตรวจ)`, `(ตามร่าง)`, `*` รายบรรทัด เพื่อให้ข้อความกระชับ แต่หากมีรายการยังไม่ยืนยันตามข้อมูล ให้แสดงคำเตือนรวมท้ายข้อความเพียงครั้งเดียว ไม่แปลงข้อมูลร่างเป็นผลรับรอง
4. รายการ 5 IDs วันที่ 18 พ.ย. ในภาพ: ทำ overlay คำยืนยันของผู้จัด *เฉพาะวันและเวลาตามที่ระบุ* โดยตรวจ ID/วัน/เวลาและทีม/ชนิดกีฬา, รักษาต้นฉบับ PDF และประวัติ, อย่าอ้างว่าผังหรือคู่รอบถัดไปยืนยันโดยอัตโนมัติ
5. ตรวจไม่ให้ R33 เดิมถูกเขียนทับ; หากยังไม่ได้ย้ายรุ่น Supabase จะรายงาน source version mismatch ว่าเว็บรับคำยืนยันห้ารายการผ่าน overlay แต่ R33 active รอซิงก์แบบเก็บประวัติ
