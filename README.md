# Nongkum Sports Hub — กีฬากลุ่มหนองกุ่ม ปี 2569

พื้นที่กลางสำหรับเก็บข้อมูลการจัดการแข่งขันกีฬา การประชุม คำสั่งคณะกรรมการ และสูจิบัตรกีฬาแบบออนไลน์

## สถานะงาน
**Mobile Program — Prototype / Draft Only** ยังไม่ใช่เว็บประกาศกำหนดการแข่งขันฉบับทางการ

ต้นแบบเว็บ `index.html` รองรับการเลือกโรงเรียนทั้ง 8 แห่ง เลือกกีฬา 9 หมวด ค้นหารุ่น/คู่แข่งขัน พร้อมแสดงแหล่งอ้างอิงหน้า PDF และป้ายวัน/เวลา/สนามที่ยังไม่ยืนยัน ข้อมูลใน `data/draft-schedule.json` เป็นตัวอย่างเพียง 46 รายการ ไม่ครบทุกโปรแกรม และทุกแถวเป็น draft

**ห้ามใช้ข้อมูลต้นแบบนี้นัดหมายผู้ปกครอง/นักกีฬา** จนกว่าผู้จัดตรวจรับและประกาศตารางจริง

## เอกสาร
- [แผนเว็บสูจิบัตรและสถาปัตยกรรม Google Sheets](docs/SPORTS_PROGRAM_WEB_PLAN.md)
- [รายการตรวจสอบ/จุดไม่ตรงในสูจิบัตร PDF](docs/SOURCE_QA_2569.md)
- [ข้อมูลตัวอย่างจาก PDF (Draft)](data/draft-schedule.json)

## ดูต้นแบบในเครื่อง
ต้องเปิดผ่านเว็บเซิร์ฟเวอร์ เพราะหน้าเว็บโหลด JSON ด้วย `fetch` (เปิด `file://` ตรงๆ ไม่ได้)

```bash
python -m http.server 8000
# เปิด http://localhost:8000
```

ตรวจความถูกต้องเชิงโครงสร้างก่อนส่ง PR:

```bash
node scripts/validate-data.mjs
```

ยังไม่ตั้งค่า GitHub Pages เพื่อหลีกเลี่ยงการสื่อสารว่าตารางร่างเป็นตารางที่เผยแพร่แล้ว หลังรับรองข้อมูลและตั้งค่าชุดข้อมูล approved ค่อยเปิดเผยแพร่บน `https://infobwd.github.io/nongkum-sports-hub/` (URL เป้าหมาย ไม่ใช่สถานะ live)

## แนวทางข้อมูล
- ข้อมูลต้นทาง: “สูจิบัตรกีฬา 69.pdf” 40 หน้า ที่ผู้จัดให้ศึกษา (PDF ไม่ได้อัปโหลดสาธารณะใน repo นี้)
- ก่อนเผยแพร่ต้องตรวจรายกีฬา/คู่/รุ่น/วัน/สนามและหมายเลขที่ซ้ำกัน
- แผนที่แนะนำ: Google Sheets จำกัดสิทธิ์แก้ไขเฉพาะผู้จัด → ตรวจ/อนุมัติ → ส่ง **approved-only JSON snapshot** → GitHub Pages อ่านอย่างเดียว
- ไม่ใส่ข้อมูลนักเรียน รูปเด็ก เบอร์โทร หรือ credential ใดๆ ใน GitHub public หรือ JSON public

## โครงสร้างโปรเจ็กต์
```
index.html                      ตัวอย่างหน้าดูสูจิบัตรบนมือถือ
data/draft-schedule.json        ข้อมูลร่างบางส่วน (ห้ามใช้เป็นข้อมูลทางการ)
docs/SPORTS_PROGRAM_WEB_PLAN.md เป้าหมาย UX สถาปัตยกรรม และ roadmap
docs/SOURCE_QA_2569.md          ประเด็นจาก PDF ที่ต้องให้ผู้จัดตรวจรับ
scripts/validate-data.mjs       ตรวจความสมบูรณ์ของ draft schema
.github/workflows/validate.yml  CI ตรวจ draft เมื่อ push/PR (ไม่ deploy)
```

## งานต่อไป
1. นำเข้ารายการครบทุกกีฬา/กรีฑาและเทียบกับ PDF ทุกหน้า (แก้ QA ที่ค้างตามมติผู้จัด)
2. สร้างชีทต้นทางที่ใช้งานง่ายและจำกัดสิทธิ์ รวมทั้ง publication gate
3. ทดสอบการ sync snapshot และจัดการข้อมูลเฉพาะ approved
4. QA มือถือและเปิด GitHub Pages เมื่อข้อมูลพร้อมใช้จริง
