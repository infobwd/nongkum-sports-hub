# R17 — กลับจากผลแข่งขันสู่ตารางเรียงเวลา และยืนยันเปตอง 12–13 พฤศจิกายน

วันที่: 5 พฤศจิกายน 2569 · อ้างอิงแผน/ผล R16, สูจิบัตร PDF ฉบับ 4 พฤศจิกายน 2569 และคำยืนยันผู้จัด

## เป้าหมายและการเปลี่ยนแปลง

1. เมื่อแตะเมนู **ตารางแข่ง** จากหน้าผลแข่งขัน `js/navigation.js` ใส่เครื่องหมาย `from=results#programListing` เฉพาะการเปลี่ยนแท็บ (คง `school/sport/level`); หน้า `js/program.js` เมื่อโหลดและเรียงข้อมูลครบจะเลื่อนไปหัวข้อโปรแกรม จากนั้นลบ `from` ออกจาก URL ด้วย `replaceState` โดยคงตัวกรอง/anchor. ไม่บังคับเลื่อนหากเป็นลิงก์แชร์คู่ `?fixture=` หรือเป็นการเปิดตารางตามปกติ.
2. การเรียงวัน–เวลาใน R16 **ไม่เปลี่ยนกติกา**: กรอง → เรียงทั้งชุด → จำกัด 12 รายการ → จัดกลุ่มวัน → โหลดเพิ่มครั้งละ 12; ไม่เปลี่ยน ID, เส้นทาง PDF, ลิงก์ LINE หรือระบบผล.
3. แสดงตัวกรองที่กำลังใช้ชัดเจนใต้หัวตาราง เพื่ออธิบายเหตุใดวันที่แรกที่เห็นแตกต่างกันเมื่อสลับหน้า.
4. เพิ่มเวอร์ชัน asset ของ `navigation.js`, `program.js`, `schedule-order.js` ใน HTML ทั้งสองหน้าเพื่อหลีกเลี่ยงการค้างของ JavaScript เก่าบน iOS/Safari/LINE.
5. เก็บ **กำหนดการแข่งขัน 24 คู่เปตอง วันที่ 12 และ 13 พฤศจิกายน 2569** เป็นข้อมูลที่ยืนยันแล้วตามคำยืนยันผู้จัด: วัน/สถานที่ที่เคยบันทึกว่าผู้ประสานงานยืนยัน 4 พ.ย. และเวลา PDF ที่ผู้จัดยืนยันตามรายการ 5 พ.ย. ค่า `planning_time` กับ `planning_time_confirmation: confirmed` เป็นฟิลด์ใหม่เฉพาะ 24 คู่; บันทึกคำยืนยันใหม่แยกใน `planning_schedule_confirmation_note` โดยรักษา `planning_source` เดิมเพื่อให้ R11A audit ตรวจย้อนกลับได้; เวลา `planning_time` มีลำดับก่อน `source_pdf.source_time` เมื่อผ่านการยืนยันแล้ว.
6. ป้ายแสดงสถานะ 24 คู่สื่อว่า **วัน เวลา และสถานที่ยืนยันแล้ว** แต่ยังคงสถานะโปรแกรมรวมเป็นข้อมูลร่าง และคง `qa_flags` พร้อมข้อความ “ข้อสังเกตจาก PDF” ไม่ลบหลักฐานประเด็นผังแข่งขันหรืออ้างว่าผลแข่งขันรับรองแล้ว.

## ขอบเขตข้อมูลที่ล็อก

- ชุดที่เว็บไซต์อ่าน: `data/program-from-pdf-2569-20261104-draft.json` มี 237 รายการ. วันที่ 12 พ.ย. 12 คู่ และ 13 พ.ย. 12 คู่; กีฬาคือเปตอง สถานที่โรงเรียนบ้านหนองกระทุ่ม เวลาตาม PDF ที่ยืนยันคือ 09:00 / 10:00 / 13:00 น. ในแต่ละวัน.
- `source_pdf`, `fixture.id`, `qa_flags`, `status: draft`, `review_status: draft`, `planning_status: review` ไม่เปลี่ยน; ข้อสังเกตต้นฉบับยังคงตรวจต่อได้.
- `data/draft-schedule.json` ที่เป็นประวัติชุด 236 รายการ **ไม่แก้**, `data/public-results.json` **ไม่แก้** และผลรับรองยังเป็น 0.
- อีก 213 รายการยังเป็นข้อมูลจาก PDF ที่รอตรวจรับตามเดิม รวม 3 รายการที่ปีในเอกสารไม่ตรง (2568) ต้องอยู่กลุ่มท้ายและไม่ถูกคาดเดาปี.

## ตรวจรับ

รัน `node scripts/ux/test-tab-return-confirmed-r17.mjs` ร่วมกับ R16 และ regression หลักใน workflow R14:
- ผลการสลับหน้า results → program ต้องมี filter เดิม, URL marker เฉพาะข้ามหน้า, เลื่อนไปหัวตาราง และไม่พาลิงก์แชร์รายคู่ไปผิดที่
- ข้อมูลยืนยัน 24 คู่มีวัน/เวลา/สถานที่ครบ; ไม่มีการแก้ค่า PDF ต้นฉบับ, QA flags หรือสถานะรับรองผลการแข่งขัน
- ตรวจ JSON 237 รายการ, วันที่ 12/13 รายละ 12 คู่, ป้ายเขียวแสดงเวลาใหม่, วันผิดปกติ 3 แถวคงท้าย
- iPhone Safari/LINE เปิดแท็บผลแล้วกลับตาราง ตรวจหน้าที่เห็นและตัวกรอง; เปิดหน้าคู่แชร์ เปิด PDF กลับคู่ และกดโหลดเพิ่มตามลำดับ

**ข้อจำกัด:** การตรวจอัตโนมัติยืนยัน logic และสัญญา UI แต่ยังต้องทดสอบการคืนตำแหน่งเลื่อนจริงบน iPhone หลัง GitHub Pages deploy.
