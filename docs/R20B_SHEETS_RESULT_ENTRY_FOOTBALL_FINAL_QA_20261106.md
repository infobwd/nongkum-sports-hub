**สถานะ:** Implemented in repository / QA with simulated Sheets — **ยังไม่ได้ติดตั้ง Apps Script ลงใน Google Sheets จริง และยังไม่ได้ทดสอบบนอุปกรณ์หรือบัญชีกรรมการจริง**  
**แผนหลัก:** [R20 — ผลการแข่งขันสามช่องทาง](R20_MULTICHANNEL_RESULTS_SHEETS_GITHUB_PLAN.md)

## 1. ฟุตบอลมัธยมหญิง — ยึดคำยืนยันผู้จัด

ผู้จัดยืนยันในแชต 6 พฤศจิกายน 2569 ว่า **ฟุตบอลมัธยมหญิงรอบชิง โรงเรียนบ้านหนองกระทุ่ม–โรงเรียนวัดทุ่งมะสัง แข่งขัน 18 พฤศจิกายน 2569 เท่านั้น** และให้ตัดบรรทัดวันที่ 20 พฤศจิกายนออกจากรายการใช้งาน

- **คง** `football-p07-มัธยมหญิง-007` (วันที่ยืนยัน `2026-11-18`).
- **ไม่นำเข้าใช้งาน** `football-p07-มัธยมหญิง-020-repeated-final` (วันที่ตามต้นฉบับร่าง `2026-11-20`).
- Google Sheets แท็บ `04_คู่แข่งขัน` มีเพียงรายการแรกอยู่แล้ว: เพิ่มวันที่ยืนยันที่ `K8` และหมายเหตุคำยืนยันที่ `R8`; ไม่เพิ่มแถวและไม่ยืนยันเวลา `L8`, สนามย่อย `M8`, ไม่เปลี่ยนสถานะ `N8`.
- สำรองชีตต้นทางก่อนแก้ไขใน Drive เดิม ใช้ชื่อ **สำรองก่อน R20-B — ตารางที่ยืนยัน 45 คู่ (6 พ.ย. 2569)**.
- `data/program-from-pdf-2569-20261104-draft.json` เป็น **หลักฐานถอด PDF ต้นฉบับ** ยังเก็บรายการ 237 ไว้เพื่อเปรียบเทียบ; ใช้ตัวปรับรายการที่ได้รับคำยืนยัน `js/program-corrections.js` เพื่อแสดง **236 รายการที่ใช้จริง** ในหน้าโปรแกรม, หน้าตรวจสูจิบัตร, หน้าที่กรรมการ และใบคะแนน A4 โดยไม่แก้ PDF หรือประวัติเดิม.
- ตัวปรับรายการตรวจว่าตรงทีมและต้นทางเดิมก่อนตัดซ้ำ, ทำซ้ำไม่เกิดรายการหายเพิ่ม และเพิ่ม `planning_date_confirmation=confirmed` เฉพาะวัน 18 พ.ย. **ไม่ยืนยันเวลาหรือสนามย่อย**.
- ลิงก์ที่เคยอ้างรหัสคู่ที่ถูกตัดจะไม่เปิดเป็นคู่แข่งขันที่ใช้งานแล้ว; เส้นทางแชร์เก่าถูกเก็บไว้เป็นหลักฐานประวัติแต่ไม่ควรส่งลิงก์ดังกล่าวต่อ.
- ข้อมูลต้นทางรายการอื่นยังคงร่าง และไม่มีการสร้างผลการแข่งขัน.

## 2. ขั้นตอนใช้งานที่เพิ่มในโค้ด Google Sheets (ภาษาทั่วไป)

เพิ่ม `apps-script/ResultEntry.gs` ใช้ร่วมกับ `Code.gs` และ `Results.gs` โดย `onOpen()` แสดงเมนู **มิตรภาพเกมส์ · บันทึกผล**:

1. **เริ่มบันทึกผลคู่แข่งขันที่เลือก** — เลือกแถวใน `04_คู่แข่งขัน`, ระบบคัดลอกรหัสคู่ กีฬารอบและโรงเรียนลง `07_ผลประเภททีมคู่`; ผู้บันทึกกรอกเฉพาะคะแนน ผู้ชนะ และรายละเอียดจำเป็น.
2. **เริ่มบันทึกผลกรีฑาที่เลือก** — เลือกแถวลู่ที่มีโรงเรียนระบุชัดเจนใน `05_กรีฑา`, ระบบเตรียมแถวใน `08_ผลกรีฑา`; ผู้บันทึกเติมอันดับ สถิติ และหน่วย. ลู่ที่ไม่มีโรงเรียนที่ตรวจได้ต้องให้ผู้จัดแก้ข้อมูลก่อน.
3. **ส่งผลที่เลือกให้ตรวจ** — ตรวจรายคู่/โรงเรียน/กติกาคะแนน, ผู้ส่ง, และการซ้ำ ก่อนเปลี่ยนสถานะเป็น `review`; ไม่เผยแพร่ผล.
4. **ยืนยันผลที่เลือก (ผู้มีสิทธิ์)** — ผู้รับรองต้องมีสิทธิ์แยกจากผู้ส่ง; รายการต้องผ่าน `review`, รายการแข่งขันต้นทางต้อง `approved` พร้อมหลักฐาน fingerprint ไม่มีการแก้หลังอนุมัติ, ผลต้องไม่ซ้ำกัน.
5. **เตรียมผลสำหรับเผยแพร่ (ผู้ดูแล)** — ใช้ตัวส่งออกเดิม `Results.gs` สร้างไฟล์เฉพาะผล Approved ใน Drive ส่วนตัว; **ยังไม่ส่ง GitHub อัตโนมัติ** (เป็นงาน R20-C).

**นโยบายภาพหลักฐาน:** ไม่บังคับภาพสำหรับผลปกติทุกชนิดกีฬา; ผู้ตรวจอาจขอภาพเมื่อคะแนนขัดแย้งหรือมีการแก้ไขภายหลัง. **ช่องทางส่งภาพผ่าน ChatGPT ยังใช้งานแบบเดิม** และต้องมีคนตรวจรับก่อนเผยแพร่.

## 3. สิทธิ์และข้อควรระวัง

- ใน Google Sheets ส่วนตัวของผู้จัด เปิด **Extensions → Apps Script** แล้วติดตั้งโค้ดล่าสุด `apps-script/Code.gs`, `apps-script/Results.gs`, `apps-script/ResultEntry.gs` ร่วมกัน; ต้องดำเนินการโดยบัญชีเจ้าของที่มีสิทธิ์.
- กำหนด **Script properties**: `NONGKUM_RECORDER_EMAILS` (บัญชีที่กรอกและส่งผลได้) และ `NONGKUM_APPROVER_EMAILS` (บัญชีที่ยืนยันผลได้) เป็นรายชื่ออีเมลคั่นด้วยเครื่องหมายจุลภาค. ค่าไม่ตั้ง/บัญชีไม่ตรง/บัญชีไม่เปิดเผยอีเมล **ปฏิเสธการทำงาน**.
- ผู้ที่มีสิทธิ์ **แก้ไข Google Sheet อาจแก้ไข bound Apps Script ได้ด้วย** จึงให้ Editor เฉพาะกรรมการที่ไว้วางใจ และป้องกันคอลัมน์ผลอนุมัติ. อย่าใส่ GitHub Token หรือกุญแจเผยแพร่ในสคริปต์ที่ผู้กรอกแก้ไขได้; งาน R20-C ต้องแยกตัวส่ง GitHub ที่ควบคุมสิทธิ์.
- ถ้าข้อมูล `04_คู่แข่งขัน` / `03_รายการ` ยังเป็น `draft/review` ผู้บันทึกยังส่งผลให้ตรวจได้ แต่ **ยืนยันผลเพื่อเผยแพร่ไม่ได้** จนผู้รับผิดชอบอนุมัติรายการต้นทางผ่านกระบวนการ P2 พร้อมหลักฐาน.
- ขั้นตอนนี้ไม่มี endpoint สาธารณะ ไม่มีการตั้งการเขียนอัตโนมัติไป GitHub และไม่มีการให้ผู้ใช้เว็บทั่วไปแก้ Google Sheets โดยตรง.
- ข้อความที่กรรมการเห็นเน้น “เริ่มบันทึกผล”, “ส่งผลให้ตรวจ”, “ยืนยันผล”, “เตรียมผลสำหรับเผยแพร่” ไม่ใช้คำว่า JSON, PR, token ในเมนู.

## 4. เกณฑ์ QA อัตโนมัติ / สิ่งที่ยังไม่ได้ตรวจ

ชุดทดสอบใหม่ `scripts/results/test-r20b-entry.mjs` และทดสอบ R8/R11D/R13/R14/R17/R18 ที่ปรับให้แสดงรายการแข่งขันที่ผู้จัดยืนยัน:

- ไม่แสดงคู่ซ้ำวันที่ 20, วันนัดชิงเป็น 18 พ.ย. โดยไม่เดาเวลา/สนาม; โปรแกรมที่ใช้จริงมี 236 รายการ แต่ต้นฉบับ PDF ร่างยังอ่านตรวจย้อนหลังได้.
- บัญชีที่ไม่อยู่รายชื่อบันทึกไม่ได้; เลือกรายการแข่งขันผิดแท็บหรือไม่ระบุโรงเรียนทั้งสองฝ่ายไม่ได้.
- เริ่มรายการครั้งเดียว, ห้ามสร้างคู่เดียวซ้ำ; ส่งผลเข้าตรวจจาก `draft` เป็น `review`.
- ห้ามยืนยันผลที่ยังไม่ส่งตรวจ/คู่แข่งขันต้นทางยังไม่รับรอง; ต้องมีสิทธิ์ผู้รับรอง และผลเผยแพร่ไม่แสดงผู้กรอก/ผู้รับรอง.
- กรีฑาเริ่มจากโรงเรียนที่มีตัวตนในลู่ และยังไม่อนุมัติได้จนรายการกรีฑาต้นทางผ่านรับรอง.
- GitHub Actions ตรวจ code / UI regression, **ไม่ใช่การยืนยันว่ามีเมนูใน Google Sheets จริง**.

**คงงาน R20-C:** แอปสคริปต์แบบสิทธิ์จำกัดสำหรับนำผล Approved ขึ้น branch/PR ใน GitHub และกระบวนการตรวจ Merge ก่อนเผยแพร่. **คงงาน R20-D:** หน้าบันทึกผลในเว็บมือถือ.
