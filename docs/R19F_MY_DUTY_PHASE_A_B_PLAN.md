# R19-F — My Duty: ค้นหาหน้าที่กรรมการรายบุคคลและเชื่อมกำหนดการแข่งขัน (Phase A–B)

**วันที่เริ่ม:** 6 พฤศจิกายน 2569 · **สถานะ:** Implementation plan; ยังไม่ใช่หลักฐานผ่านตรวจรับหน้างาน  
**Repo:** `infobwd/nongkum-sports-hub` · **ต้นทาง:** `committee.html`, `js/committee.js`, `data/committee-2569-draft-public-review.json`, `data/program-from-pdf-2569-20261104-draft.json`  
**ข้อกำหนด:** Commit แผนก่อนแก้ data/UI; ไม่แก้ข้อมูลต้นทาง, ไม่อนุมัติรายการอัตโนมัติ

## 1. ปัญหาและผลที่ต้องการ

รายงานกรรมการเดิมมุมมอง 4 แท็บเหมาะสำหรับผู้จัด แต่ครูต้องเลือกหลายตัวกรองและชื่อคนเดียวอาจปรากฏหลายงาน ผู้ใช้งานควรเลือกโรงเรียน + พิมพ์ชื่อแล้วเห็น **รายการหน้าที่ทุกบรรทัด** ของชื่อนั้น เรียงตามวันที่ที่มีหลักฐาน พร้อมสถานะความเชื่อมั่นและทางไปตรวจรายชื่อเดิม

### หลักฐานปัจจุบัน
- ชุดสาธารณะจากสูจิบัตรร่างปี 2569: 250 **บรรทัดหน้าที่**, 151 **ข้อความชื่อแตกต่าง** (ไม่ใช่จำนวนบุคคลยืนยัน), 20 ฝ่าย, โรงเรียน 8 แห่ง; บางบรรทัดไม่มี school_id, กีฬา หรือรุ่น
- ชุดรายการแข่ง candidate 237 fixtures / 9 sports / 33 divisions; ณ วันที่ 6 พ.ย. มี 45 รายการวัน-เวลา-สถานที่ยืนยัน; วันใน `draft_date` เป็นร่าง ไม่ใช่วันปฏิบัติหน้าที่
- ยังไม่มีการรับรองแต่งตั้งกรรมการปี 2569; รายชื่อสาธารณะเพื่อตรวจความถูกต้องเท่านั้น; มี `committee-review.html` แยกสำหรับโรงเรียน

## 2. ล็อกขอบเขตระยะ A — Individual Lookup

1. เพิ่ม section **หน้าที่กรรมการของฉัน** ก่อนแผงภาพรวม (หรือก่อนตัวกรองรายงาน) โดยไม่ลบ 4 แท็บเดิม
2. ตัวเลือกโรงเรียนจาก `roster.schools` + ค้นหาไทยแบบไม่สนเว้นวรรคย่อย/ตัวพิมพ์ใหญ่ ให้ตัวเลือกผลตรงโรงเรียน; ใช้การเลือกผล `school_id + name` ไม่จับคู่คนจากชื่อข้ามโรงเรียน
3. แสดงแถวชื่อที่เลือกทั้งหมดแบบไม่บีบรวมหน้าที่: `role`, `section`, `sport_id`, `subdivision`, `pdf_page`, `flags`; ติดป้าย **ร่าง/รอตรวจ** เสมอ
4. กรณีชื่อเหมือนกันในโรงเรียนหรือข้อมูลไม่พอ: ไม่อ้างว่าเป็นคนเดียวจริง; ป้ายเตือนให้ตรวจ; ให้ผลตามข้อความชื่อ-โรงเรียนในเอกสารเท่านั้น
5. ทางลัดไป `committee-review.html` แยก role-based review เดิม; ไม่มี write-back, ไม่มี login ใหม่, ไม่เผยแพร่ข้อมูลนอกชุด public ที่มีอยู่
6. ผลไม่พบ: “ไม่พบชื่อนี้ในชุดร่างตามเงื่อนไข” ไม่ใช่ “ไม่ได้เป็นกรรมการ”
7. ใช้ DOM `textContent` สำหรับข้อมูลจาก JSON; keyboard/mobile accessible; ค้นหาอัปเดตทันที, ไม่มีสถานะค้างหลังรีเฟรช

## 3. ล็อกขอบเขตระยะ B — คิววันแข่งขันที่เกี่ยวข้อง

1. โหลด **ข้อมูล candidate เดียวกับโปรแกรม** จาก `data/program-from-pdf-2569-20261104-draft.json` แบบ read-only และแยก failure ไม่ให้การค้นหารายชื่อพัง
2. **ห้ามสร้างวันปฏิบัติงานกรรมการจากวันแข่งขัน**; card ติดป้าย “วันปฏิบัติหน้าที่: รอผู้จัดยืนยัน” เสมอจนมีชุด duty schedule ที่รับรองจริง
3. สำหรับรายการที่มี `sport_id` จับคู่เฉพาะกีฬานั้น; วันที่กีฬาใช้จาก fixtures `date` ที่ confirmed เท่านั้นในการแสดง “วันแข่งขันยืนยัน”; แสดงวัน `draft_date` แยกเป็น “กำหนดการแข่งขันร่าง” และไม่ตีความ `draft_date` เป็น confirmed
4. ไม่ map คน → ทุกคู่/ทุกรุ่นโดยอัตโนมัติ; สิ่งที่แสดงคือ **วันแข่งระดับชนิดกีฬาเพื่อประกอบการตรวจ**, ไม่ใช่การมอบหมายกรรมการลงคู่
5. กลุ่มทั่วไป (`sport_id=null`) ไม่ผูกวันแข่งขันใด จะแสดง “ยังไม่ได้เชื่อมกับกำหนดการแข่งขัน”
6. หาก candidate โหลดไม่ได้ ให้ข้อความเตือนเฉพาะวันแข่งขัน, หน้าค้นหาครูยังทำงาน
7. วันเวลาแสดงตามโซนประเทศไทย, เรียงวันที่จริง, รวมวันซ้ำโดยไม่รวมบทบาทซ้ำ, ระบุสถานะทุกวัน
8. ไม่สร้าง field `duty_date` สมมติ; ระยะ C จึงค่อยมี data contract และข้อมูลมอบหมายรายบุคคลจากผู้จัด

## 4. ขอบเขตไฟล์

แก้เฉพาะ `committee.html`, `css/committee.css`, `js/committee.js`; เพิ่ม `tests/r19f-my-duty.test.js` ตามโครงสร้างทดสอบเดิมหากเหมาะสม; แผนนี้อยู่ `docs/R19F_MY_DUTY_PHASE_A_B_PLAN.md`. ไม่แก้ `committee-review.html`, `js/committee-review.js`, JSON ต้นทาง/ระเบียบรับรอง, ตารางคะแนน และรายการแข่งขัน
