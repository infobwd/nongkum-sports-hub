## ขอบเขต JSON
- `school_crosswalk`: เชื่อม `sport_program_school_id` (กีฬา) กับ `sillapa_school_id` แบบ string; ไม่ใช้ชื่อโรงเรียนเป็น primary join key
- `legacy_committee_groups`: ฝ่าย 1–20 จากคำสั่งปี 2568 เพื่อเป็นแม่แบบหน้าที่เท่านั้น
- `sports`: 9 ชนิดกีฬา พร้อมเลขหัวข้อเก่าที่อ้างอิงได้/ไม่ได้; `assignments_2569: []` จนกว่าจะรับรอง
- `divisions`: 33 รุ่นตามต้นทาง candidate; ไม่มีการเดารุ่นกรีฑา
- `review_flags`: ปีเก่า, หัวข้อ 14.6 ซ้ำ, ยิงจุดโทษไม่มีคณะกรรมการเฉพาะในคำสั่งเดิม, สนามเปตองปีเก่าต่างจากวันนอกรอบ 2569, และข้อจำกัดทะเบียนครู
- ไม่มีชื่อครู เลขทะเบียนครู `T-...`, เบอร์โทร อีเมล ชื่อผู้อนุมัติ หรือ Google Docs/Sheet IDs ใน public JSON

## การออกแบบหน้าเว็บระยะถัดไป
**UI A: สรุปภาพรวม** แสดงชนิดกีฬา 9 หมวด รายการรุ่นที่เกี่ยวข้อง จำนวนฝ่ายจากแม่แบบ และสถานะมอบหมายปี 2569 แบบไม่ทำให้เข้าใจว่าได้รับแต่งตั้งแล้ว

**UI B: ดูตามกีฬา/รุ่น** เลือกกีฬา → รุ่น → ประเภทหน้าที่ (ประธาน, ตรวจหลักฐาน, ตัดสิน, บันทึกผล, เลขานุการ); แสดง “รอแต่งตั้ง” เมื่อไม่มีชื่อ

**UI C: ดูตามฝ่าย** รองรับงานกลาง เช่น อำนวยการแข่งขัน, ประชาสัมพันธ์, พยาบาล, บริการ, สนาม, การเงิน, รางวัล, ถ่ายภาพ, บันทึกผล และคณะกรรมการกรีฑา 15–19

**UI D: สำหรับผู้จัด** จัดทำในระบบจำกัดสิทธิ์ภายหลัง: ค้นหาครูจากทะเบียนที่โรงเรียนยืนยันแล้ว, เสนอชื่อ, ตรวจชื่อ/โรงเรียน, พบหน้าที่ซ้ำ/เวลาทับซ้อน, รับรองโดยผู้จัด; มี audit trail ของผู้ตรวจที่ไม่ออก public JSON

**Publication gate** เผยแพร่เฉพาะข้อมูลบทบาทได้ทันที; ชื่อกรรมการต้องมีหลักฐาน `committee_approved` และการอนุญาตเผยแพร่ตามวัตถุประสงค์งานกีฬาแยกจากความยินยอมหรือการอนุมัติใน Sillapa

- ทั้ง 9 ชนิดกีฬาและ 33 รุ่นต้องครบ ไม่ซ้ำ; school crosswalk 8 แห่ง one-to-one

- R10 คิวประกาศ / R12 นักกีฬาซ้ำ / R15 ผลและอันดับ เป็นโมดูลแยก: R19 ไม่แก้ `results.html`, `standings.html`, `data/public-results.json`, `apps-script/Results.gs` หรือ fixture IDs

1. ผู้จัดรับรองโครงสร้างฝ่าย/ชนิดกีฬาและยืนยันตัวบุคคลปี 2569 จากคำสั่งฉบับใหม่
