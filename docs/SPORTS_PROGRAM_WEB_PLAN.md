## 1. เป้าหมายและขอบเขต

- ผู้ใช้งานหลักคือ **ผู้ปกครองและครูบนโทรศัพท์มือถือ**: หาโรงเรียนของตน → เห็นรายการที่แข่ง เวลา สนาม คู่แข่งขัน การเปลี่ยนแปลงล่าสุด โดยไม่ต้องค้น PDF
- ผู้จัด/กรรมการ: ตรวจทานต้นฉบับ กำหนดวัน/เวลา/สนาม ยืนยันการประกาศ อัปเดตผล และออกข้อความแจ้งเตือน โดยแก้ข้อมูลใน Google Sheets แทนการแก้โค้ด
- เปิดสาธารณะเฉพาะข้อมูลโปรแกรมที่ผ่านการยืนยัน ไม่เผยแพร่รายชื่อนักเรียน/ภาพเด็ก/เบอร์โทรศัพท์ใน MVP
- **ไม่ใช่ระบบสมัครทีม/จัดการทะเบียนนักกีฬา** และ **ไม่อ้างว่าเป็นรายงานผลทางการ** จนกว่าจะผ่านกระบวนการตรวจรับ
- ต่อยอดเป็นสูจิบัตรส่งโรงพิมพ์ A4/PDF หรือ QR Code หน้าโรงเรียนและสนามได้ในอนาคต

## 2. สิ่งที่มีในสูจิบัตร (ต้องรักษารูปแบบจริง)

- กลุ่มโรงเรียน 8 แห่ง: บ้านหนองกุ่ม, วัดทุ่งมะสัง (มิตรภาพที่ 9), บ้านรางขาม, บ้านวังด้ง, บ้านพุพรหม, บ้านวังเขาแก้ว, บ้านเสาหงส์, บ้านหนองกระทุ่ม
- หมวดกีฬา/กิจกรรมที่ผู้ปกครองต้องค้นหา: ฟุตบอล, ยิงจุดโทษปฐมวัย, ฟุตซอล, วอลเลย์บอล, เซปักตะกร้อ, เปตอง, เทเบิลเทนนิส, ชักเย่อ, กรีฑา (จักรยานขาไถรวมในกรีฑาตามต้นฉบับ)
- โปรแกรมประเภทคู่หรือทีม (หน้า 7–22); กรีฑาและลู่แข่งขัน (หน้า 23–35); รายชื่อนักกีฬา (หน้า 36 — ยังไม่เผยแพร่); สรุปคะแนน (หน้า 37–40)
- ฟุตบอลมีเวลาบางคู่ระบุแล้ว แต่คอลัมน์วันแข่งเว้นว่าง; กีฬาอื่นหลายรายการมีคู่แข่งขันแต่ยังไม่ระบุเวลา/สนาม
- เกณฑ์คะแนนประเภททีม/บุคคลในต้นฉบับ: ที่ 1 = 5, ที่ 2 = 3, ที่ 3 = 2 (หน้า 1) **ยังไม่ทำคะแนนรวมอัตโนมัติ** จนกว่าผู้จัดยืนยันหลักเกณฑ์แต่ละประเภท

## 3. ประสบการณ์มือถือ (Mobile-first)

### หน้าแรก: “ดูโปรแกรมการแข่งขัน”
1. หัวเว็บ: ชื่องาน, ปี, ชิปสถานะข้อมูล (ร่าง / ยืนยันแล้ว), อัปเดตล่าสุด
2. ตัวเลือก **“โรงเรียนของฉัน”** เด่นที่สุด: เลือกจาก 8 โรงเรียนและจดจำไว้ในเครื่อง (localStorage)
3. ปุ่ม/ชิป: วันนี้, วันอื่นๆ (แสดงเมื่อทราบวันจริง), กีฬา, ระดับชั้น/รุ่นอายุ, ค้นหาชื่อโรงเรียน
4. ผลลัพธ์เป็น **การ์ดแนวตั้ง** ไม่ใช่ตารางกว้าง: เวลา → กีฬา/รุ่น/รอบ → ทีม A vs ทีม B → สนาม → สถานะ
5. การแข่งขันแบบกรีฑาแสดงชื่อรายการ/รุ่นและป้ายลู่การแข่งขัน; ไม่ฝืนแสดงเป็น A vs B
6. บอก **“ยังไม่กำหนดเวลา”** เมื่อเป็นค่าว่าง ไม่ใส่เวลาคาดการณ์
7. แถบ “ประกาศจากผู้จัด” เฉพาะข่าวที่อนุมัติแล้ว
8. ลิงก์ “สูจิบัตรต้นฉบับ PDF” เมื่อไฟล์ได้รับอนุญาตให้เผยแพร่; ปรับเพื่อการเข้าถึงด้วยขนาดปุ่ม ≥44px, ฟอนต์ไทยอ่านง่าย, contrast, ไม่ใช้สีอย่างเดียวแทนสถานะ

### หน้ารายละเอียด
- กีฬาหนึ่งประเภท: เลือกเพศ/รุ่น/กลุ่ม (A/B), รอบแรก–รอง–ชิง, จัดเวลา/สนามและเลขคู่
- สายแข่งขัน/bracket: ใช้เมื่อระบุความสัมพันธ์ผู้ชนะคู่ก่อนหน้าอย่างชัดเจน; ไม่สมมติทีมเข้ารอบ
- กรีฑา: แสดงรายการ + ลู่/โรงเรียน (และเพิ่มเวลาต่อเมื่อกำหนด)
- หน้าประกาศ: เวลาแก้ไข, ผู้อนุมัติ, เนื้อหาประกาศ, ลิงก์ประกาศที่คัดลอกได้

## 4. สถาปัตยกรรมที่แนะนำ

```text
Google Sheets (เฉพาะผู้จัดแก้ไข + protection/validation)
    │
    ├── Draft / Review / Approved + QA validation
    │
    └── Export เฉพาะแถว Approved เป็น public-schedule.json
             │ (ผ่าน Apps Script / GitHub Action ตามที่ทดสอบได้จริง)
             ▼
       GitHub Repository (public JSON snapshot)
             │
             ▼
       GitHub Pages (static mobile web; read-only)
             │
             └── ตัวเลือกโรงเรียน + กีฬา + วันแข่ง, กรีฑา,
                 สถานะ/ประกาศ, แสดงข้อมูลอัปเดตล่าสุด
```

**เหตุผล:** หน้าเว็บสาธารณะบน GitHub Pages ไม่ควรมี API key, token หรือรหัสผ่านใดๆ; ใช้ JSON ที่ได้รับอนุมัติและตรวจสอบแล้วบนโดเมนเดียวกันหลีกเลี่ยงปัญหา CORS และแยกสิทธิ์เขียนออกจากผู้ชมได้ง่าย

**นโยบายอัปเดต:** ระหว่างเตรียมงานใช้การ publish เป็นรอบหรือเมื่อผู้จัดกดอนุมัติ; วันแข่งต้องทดสอบ latency/cache และกำหนดช่องทางประกาศฉุกเฉินก่อนอ้างว่าเป็น “สด”. หน้าเว็บต้องบอก timestamp ของข้อมูลจริง และข้อความ “กำหนดการอาจเปลี่ยนตามประกาศสนาม”.

**ข้อห้าม:** ห้ามใส่ service-account JSON, secret, Google Apps Script edit endpoint ที่เขียนได้โดยไม่มี auth, ชื่อ-สกุลนักเรียน หรือหมายเลขโทรศัพท์ใน repository/JSON public

## 5. Google Sheets: โครงสร้างดูแลง่าย 6 แท็บ

| ชีท | เนื้อหา | หมายเหตุ |
|---|---|---|
| 01_ตั้งค่า | ชื่องาน ปี ป้ายสถานะ วันเผยแพร่ ลิงก์ข้อมูล | ให้แก้เฉพาะหัวหน้างาน |
| 02_โรงเรียน | school_id ชื่อเต็ม ชื่อย่อ ชื่อที่พบใน PDF | ID คงที่ ไม่ผูกกับการสะกด |
| 03_รายการ | event_id กีฬา รุ่นอายุ เพศ กลุ่ม ประเภทแข่งขัน | เช่น futsal-u10-boys-A หรือ athletics-u8-girls-80m |
| 04_คู่แข่งขัน | match_id event_id คู่ที่ตามต้นฉบับ รอบ ทีมA/ทีมBหรือเงื่อนไขผู้ชนะ วัน เวลา สนาม สถานะ ผล | 1 แถว/คู่; อย่าใช้ “คู่ที่” เป็น ID ทั่วระบบ |
| 05_กรีฑา | heat_id event_id รายการตามต้นฉบับ รอบ ลู่ โรงเรียน วัน เวลา สถานะ | 1 แถว/ลู่/โรงเรียน; รองรับเลขรายการซ้ำ |
| 06_ประกาศ | notice_id เนื้อหา ระดับความสำคัญ เผยแพร่เมื่อ สถานะ | เผยแพร่เฉพาะ Approved |

ทุกตารางที่เผยแพร่ควรมี `source_page`, `review_status` = draft/review/approved, `updated_at` และ `updated_by` (ข้อมูลผู้แก้ไม่ต้องส่งเข้า public JSON) พร้อม Data Validation, protected columns และ version history ของ Google Sheets

### รูปแบบรายการคู่แข่งขันขั้นต่ำ
```json
{
  "match_id": "football-u12-boys-m001",
  "event_id": "football-u12-boys",
  "source_match_no": "1",
  "source_page": 7,
  "team_a_id": "thungmasang",
  "team_b_id": "phuphrom",
  "date": null,
  "time": "09:00",
  "venue": "สนาม 1",
  "round": "รอบแรก",
  "review_status": "draft"
}
```
วันเป็น `null` เพราะต้นฉบับเว้นว่าง ไม่ถือว่าแข่งวันที่ 4 พ.ย.

## 6. การจัดการของผู้จัด (ออกแบบเตรียม ไม่เปิด write endpoint ในเว็บสาธารณะ)

- ระยะแรก: ผู้จัดแก้ Google Sheets โดยตรง (dropdown/conditional formatting/ป้องกันคอลัมน์รหัส/ตรวจรายการซ้ำ)
- ระยะถัดไป: dashboard ผู้จัดแบบ login ที่ server-side ตรวจผู้มีสิทธิ์ หรือ Apps Script UI ภายในบัญชีที่ได้รับอนุญาต; ห้ามใช้ PIN/password ฝัง JavaScript ใน GitHub Pages
- กระบวนการเผยแพร่: เจ้าหน้าที่แก้ไข → ผู้รับผิดชอบตรวจรายการ → อนุมัติ → ส่ง JSON เผยแพร่ → บันทึกเวลาอัปเดต → ประกาศแก้ไข
- ผลการแข่งขันที่เผยแพร่ต้องแยก **บันทึกชั่วคราว** ออกจาก **ยืนยันผล** และแก้ไขย้อนหลังได้พร้อม audit trail
