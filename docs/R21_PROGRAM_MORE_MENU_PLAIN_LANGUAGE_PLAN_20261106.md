# R21 — ย้ายทางเข้าสูจิบัตร/กรรมการเป็นเมนู «เพิ่มเติม» และปรับภาษาหน้าตารางแข่ง

วันที่: 6 พฤศจิกายน 2569 · ขอบเขต: หน้า `index.html` (ตารางแข่ง) เท่านั้น

## เหตุผล
ภาพหน้าจอมือถือมีการ์ด “เอกสารสูจิบัตรและแจ้งแก้ไขข้อมูล” และ “กรรมการและฝ่ายจัดการแข่งขัน” สูงและบดบังรายการแข่งขันหลัก ทั้งที่หน้าตารางควรให้ค้นหา/ดูการแข่งขันได้ก่อน

## วิธีดำเนินการ
1. ย้ายลิงก์เดิม `./review.html` และ `./committee.html` ไปเป็นสองรายการใน `<details>` เมนู “เพิ่มเติม” มุมขวาบน (ไม่เพิ่มแท็บล่าง) รองรับคีย์บอร์ดและมือถือ; เมนูย่อยใช้ข้อความสั้นทั่วไป
2. ลบการ์ดลิงก์สองใบเดิมออกเท่านั้น โดยยังเก็บลิงก์สูจิบัตรตามหน้าในแต่ละคู่แข่งขัน `./pdf-viewer.html?page=...`, deep link, ระบบแชร์, และหน้ากรรมการที่แยกอยู่ตามเดิม
3. ปรับถ้อยคำที่หน้าโปรแกรม (ตัวเลือกเพิ่มเติม, ปุ่มอัปเดต, ข้อความข้อผิดพลาด/เอกสารผู้จัด) และย่อข้อความสถานที่ โดยคงข้อมูลจำนวนรายการที่ยืนยันและรอการตรวจไว้ชัดเจน
4. จำกัด CSS ให้หน้าโปรแกรม ไม่แตะ CSS ทั่วไซต์/ระบบข้อมูล; ไม่เปลี่ยนโครงสร้าง JSON, กติกา, ผลแข่งขัน, และระบบรับรองกรรมการ
5. เพิ่ม regression test ตรวจเมนูและตำแหน่งลิงก์/ตัวคัดกรอง/แท็บเดิม และรันทดสอบเดิมผ่าน GitHub Actions ก่อน merge

## พื้นที่เสี่ยงและการตรวจรับ
- ตรวจเมนูบนมือถือหน้าจอแคบ/desktop: ไม่ดันโลโก้หรือทับแท็บล่าง, เปิด-ปิดได้ด้วย `summary`, focus ชัดเจน
- ตรวจ `index.html` ยังมี `#school`, `#sports`, `#advancedFilters`, `#scheduleDaySwitch`, `#refreshProgram`, `#cards`, `#mobileTabNav` เหมือนเดิม
- ตรวจไม่มีการแก้ `review.html`, `committee.html`, `js/pdf-viewer.js`, ระบบผลการแข่งขัน/อันดับ และชุดข้อมูล
- เฝ้าระวัง PR คู่ขนานแก้เอกสารกรรมการและ PDF (เช่น PR #73) ก่อน merge: ถ้า `main` เปลี่ยนให้ตรวจ conflict และ rerun tests
- ไม่ถือว่า merged เท่ากับผ่านตรวจรับ Safari/iPhone/Android จริง ต้องมีการตรวจหน้าจอภายหลังเผยแพร่

## ข้อยกเว้น
การเปลี่ยนคำในหน้ากรรมการ/สูจิบัตรทั้งหมดและการปรับสถานะ “ร่าง” ต้องแยกตามการรับรองจริงในสายงานนั้น ไม่เหมารวมเป็นงาน UI นี้
