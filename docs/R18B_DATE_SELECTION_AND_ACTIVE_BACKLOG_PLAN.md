# R18-B — เลือกวันที่แข่งขันบนมือถือและคงโหมดแสดงวันถัดไป (Plan-first)

วันที่จัดทำ: 6 พฤศจิกายน 2569 · Repository: `infobwd/nongkum-sports-hub` · ฐานโค้ด: R18 (#41) / R17 (#40) / R16 (#38)
สถานะเริ่มต้น: **PLAN — ยังไม่แก้โค้ด/ข้อมูลแข่งขัน**. ผู้จัดร้องขอให้บันทึกแผนก่อนลงมือ.

## เป้าหมายและหลักฐาน
- ปัจจุบัน `index.html` มีเพียง `upcoming` และ `all`; `js/program.js` มี `state.dayMode`, `sessionStorage` คืนค่าเมื่อกลับจากผล, ใช้ `NongkumScheduleOrder.sortedFixtures / nearestDay / groupVisible / bangkokToday` และแบ่งโหลดทีละ 12
- candidate `data/program-from-pdf-2569-20261104-draft.json`: 237 รายการ, 7 วันที่ระบุในปี 2569 คือ 12, 13, 16, 17, 18, 19, 20 พฤศจิกายน (12 / 12 / 73 / 38 / 33 / 37 / 29 รายการ); 3 รายการมีปี 2568 ใน PDF ต้องคง **รอยืนยันวัน** ไม่แปลงปีเอง
- เฉพาะเปตอง 24 รายการ วันที่ 12–13 พ.ย. มีหลักฐานยืนยันวัน/เวลา/สถานที่ครบใน JSON; 213 รายการไม่เท่ากับได้รับการอนุมัติทั้งโปรแกรม
- ผู้จัดแจ้งสถานที่หลักของทุกชนิดกีฬาเป็น **โรงเรียนบ้านหนองกระทุ่ม**; ต้องตรวจว่าฟิลด์สนามย่อย/สถานะอนุมัติของแต่ละรายการถูกจัดทำตามหลักฐานหรือไม่ในงาน DATA/R11E แยก ไม่ใช้ UI นี้ใส่ `confirmed` แทนกรรมการ

## ขอบเขตที่ลงมือได้หลังบันทึกแผน
1. เพิ่มโหมดที่สาม `date` เป็นปุ่ม/แท็บ `วันนี้ / วันแข่งขันถัดไป | เลือกวันที่ | ทุกวัน` ในตำแหน่งเดิม ให้แตะได้สะดวกบน iPhone; คง `upcoming` เป็นค่าเริ่มต้นทุกครั้งที่เปิดหน้าใหม่
2. โหมด `date`: แสดงปุ่มวันที่ที่มีอยู่จริงแบบเลื่อนแนวนอน พร้อมจำนวนรายการในวันนั้น, เลือกได้ทีละวัน, ปุ่ม/ชิป `รอยืนยันวัน` สำหรับแถวไม่ทราบวัน; อาจมีตัวเลือก `<input type="date">` เป็นทางเลือกการเข้าถึง ไม่จำกัดการเลือกจากข้อมูลที่มีเท่านั้น; เมื่อไม่มีรายการในวันที่เลือกให้แสดง empty state ชัดเจน ไม่แอบสลับโหมด
3. คำนวณตัวเลือกวันที่ **จากผลที่กรองแล้ว** ตามโรงเรียน/กีฬา/ช่วงชั้น/ค้นหา แล้วเรียงวันจริงจาก `effectiveDay`; เปลี่ยนตัวกรองให้เลือกวันที่มีรายการที่ใกล้ที่สุดอย่างมีเหตุผล หากวันเดิมหาย และบอกผู้ใช้ ไม่แก้ JSON
4. ใช้ตรรกะ R16 เรียงก่อนจำกัด 12; ปรับหัวกลุ่มวันให้สะท้อนยอดของวันนั้น **ไม่ใช่จำนวนเฉพาะที่แสดง 12 แรก** โดยข้อความ `แสดง 12 จาก 73 รายการ` เมื่อจำเป็น
5. รักษา selected mode + selected day ระหว่างหน้า `results.html` → `index.html?from=results#programListing` **เฉพาะ session เดิม**; direct deep link `?fixture=` ต้องไม่ถูกปิดด้วยตัวกรองวัน; ไม่ให้เปิดหน้าเว็บใหม่แล้วติด date mode เดิม
6. รักษาฟีเจอร์เดิม: ตัวกรองโรงเรียน/กีฬา/ช่วงชั้น/คำค้น, แสดงเพิ่มครั้งละ 12, LINE share, PDF deep link + return, Safari/LINE Safe Area, approved-only results และ R15 standings
7. ลดการรบกวนของข้อความรีเฟรช/ช่องว่างได้เฉพาะใน scope presentation; ห้ามแก้ผล, กติกา, engine, source provenance หรือรหัส fixture

## Regression/QA gate
- `upcoming` ยังแสดงวันที่ 12 พ.ย. 12 รายการ เมื่อวันนี้ 6 พ.ย. ตามเวลา `Asia/Bangkok`; รองรับช่วงก่อน ระหว่าง และหลังวันแข่งขัน; `all` ยังเห็นครบ 237 รายการรวม 3 รายการรอยืนยันวัน
- `date` แสดง 7 วัน + รายการรอยืนยัน, กรองแล้ววัน/จำนวนรีคำนวณ, เลือกวันที่ไม่มีรายการแสดงผลว่างที่เข้าใจได้, จำนวนหัวกลุ่มไม่ผิดหลัง pagination
- กลับจากผลแข่งขันแล้วจำค่า `date`; เปิดหน้าโดยตรงใหม่เป็น `upcoming`; ไม่ทำลาย direct fixture / share / PDF
- ตรวจ script ที่มีอยู่ R16–R18 และเพิ่มชุด automated regression สำหรับ R18-B; ตรวจ syntax และ CI ก่อน Merge; การทดสอบจำลองไม่แทน mobile device acceptance
- QA มือถือจริง iPhone Safari/LINE WebView/Android, keyboard date input, landscape, font-scale, bottom safe area หลัง GitHub Pages deploy ก่อนอ้าง PASS ภาคสนาม
