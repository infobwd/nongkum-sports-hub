# UX-P2.2 — หน้าสูจิบัตรกีฬากลุ่มหนองกุ่มแบบกระชับบนมือถือ

สถานะ: **พัฒนาโค้ดแล้ว / รอตรวจรับบน iPhone และ Android จริง**  
ขอบเขต: หน้าเว็บ `index.html` เท่านั้น ไม่มีการเปลี่ยนแถวโปรแกรมการแข่งขันจาก P1 หรือฐานข้อมูล/การรับรอง P2

## เป้าหมายจากภาพหน้าจอ iPhone (4 พ.ย. 2569)

1. ลดระยะเลื่อนจากส่วนหัวจนเห็นโปรแกรมแข่งขัน
2. ให้ผู้ปกครองทำสองอย่างก่อน: **เลือกโรงเรียน → เลือกกีฬา**
3. ให้การ์ดคู่แข่งขันสูงน้อยลงโดยไม่ทิ้งข้อมูลอ้างอิง PDF
4. แสดงยอดของกีฬาแต่ละชนิดในตัวเลือก เพื่อเข้าถึงเปตองหรือกรีฑาได้ทันที แม้รายการฟุตบอลอยู่ต้นสูจิบัตร
5. ลดโอกาสที่เนื้อหาซ้อนทับบริเวณสถานะแถบ iPhone (safe area)
6. คงข้อความเตือนข้อมูลร่างและการไม่รับรอง วันเวลา/สนามอย่างชัดเจน

## สิ่งที่แก้

- หัวเว็บเหลือชื่อโครงการ โลโก้ สถานะข้อมูลร่าง และหัวเรื่องสั้น
- ส่วนตัวกรองหลักประกอบด้วย `โรงเรียนของฉัน` และชิปกีฬา ซึ่งมีจำนวนรายการที่ตรงกับโรงเรียน/ช่วงชั้น/คำค้น (ไม่นับตัวกรองกีฬาเดิม เพื่อให้เปลี่ยนกีฬาได้ด้วยการแตะครั้งเดียว)
- `<details>` สำหรับตัวกรองเพิ่มเติม เก็บการค้นหาข้อความและตัวกรองช่วงชั้น โดยเมื่อเปิด URL พร้อม `?level=...` จะขยายตัวกรองอัตโนมัติ
- ย่อคำเตือนสถานะร่างให้ไม่บดบังผลการค้นหา แต่ยังระบุ `ยังไม่ผ่านการรับรอง` และ `ห้ามใช้แทนกำหนดการทางการ`
- การ์ดแสดงชื่อกีฬา/รุ่น คู่แข่งขัน และสถานะวันเวลา/สนามก่อน ส่วนชื่อคู่ต้นฉบับ รอบการแข่งขัน หน้า PDF และ QA flags อยู่หลังปุ่ม `รายละเอียด · ข้อมูลร่าง`
- การ์ดกรีฑาคงแสดงลู่โรงเรียนที่เลือกและ `ดูทุกลู่` ได้ตาม UX-P2.1
- แถวหัวกลุ่มกีฬาบอกจำนวนทั้งหมดและจำนวนที่แสดง เช่น `12 รายการ · แสดง 4`; ยังคงปุ่มแสดงเพิ่มครั้งละ 12
- เพิ่ม `--safe-top: env(safe-area-inset-top,0px)`, safe-area padding, `scroll-padding-top`, viewport-fit และ fixed scrim บริเวณด้านบน iOS เพื่อกันเนื้อหาที่เลื่อนลอดใต้แถบสถานะ
- ไม่เปลี่ยน CSS ธีมหลักน้ำเงิน/เหลืองหรือเกณฑ์ข้อมูลจากสูจิบัตร
- ยังเป็นเว็บข้อมูลร่าง ไม่เปลี่ยน P2/P3/การอนุมัติ

## ตรวจสอบใน GitHub Actions

- `node scripts/validate-data.mjs` — จำนวน P1 จาก PDF ตรง 186 คู่ + 50 กรีฑา/289 ลู่ และ draft gate ไม่เปลี่ยน
- `node scripts/p2/test-approval.mjs` — การรับรองข้อมูลและ private snapshot ของ P2 ไม่เสียหาย
- `node scripts/ux/test-mobile-ui.mjs` — ทดสอบข้อมูลจริง 236 รายการ, กรองโรงเรียน/ช่วงชั้น/กีฬา, counts ต่อชิป, รายละเอียด HTML ที่ยุบได้, XSS escaping, URL params, pagination, source refs และ CSS safe area

## Manual visual QA — ต้องตรวจบนเครื่องจริง

- [ ] iPhone Safari เปิดครั้งแรก: ส่วนหัวไม่หายใต้ status bar และส่วนค้นหาไม่สูงเกินไป
- [ ] iPhone Safari เมื่อเลื่อนถึงท้ายหน้า: เนื้อหาที่เลื่อนลอดบริเวณ status bar ถูกบังด้วย fixed scrim และไม่ปิดปุ่มหรือข้อความที่ใช้งานจริง
- [ ] iPhone หากเพิ่มเว็บเป็น Home Screen (standalone): safe-area-inset-top และด้านล่างไม่บดบังการควบคุม
- [ ] Android Chrome ขนาด 320–430px: ช่องเลือกโรงเรียน/ชิปกีฬาไม่ล้นหน้าจอ
- [ ] เลือกโรงเรียนบ้านวังด้ง: จำนวนในชิปกีฬาเปลี่ยนตามโรงเรียนนั้น
- [ ] แตะชิปเปตองโดยไม่ต้องเลื่อนผ่านฟุตบอล: เห็นรายการเปตองทันที
- [ ] เปิดตัวกรองเพิ่มเติม เลือกประถม แล้วเปิดลิงก์แชร์ `?level=primary`: แสดงตัวกรองที่ใช้อยู่
- [ ] กดรายละเอียดของคู่ฟุตบอลและเปตอง: เห็นรอบ หน้า PDF และ QA flags (ถ้ามี)
- [ ] กรีฑาของโรงเรียน: เห็นเฉพาะลู่ของโรงเรียนนั้นก่อน, เปิดดูทุกลู่ได้
- [ ] ใช้ขนาดตัวอักษร 125–200%, VoiceOver/TalkBack และทดสอบแตะ/โฟกัส summary ด้วยคีย์บอร์ด
- [ ] เมื่อไม่มีผลลัพธ์ ปุ่มแสดงเพิ่มถูกซ่อนอย่างถูกต้อง

## แนวทางทบทวนต่อ
