## วิธีบันทึกและมาตรฐานความปลอดภัย
1. เก็บรายการที่อ่านชัดและตรงกับ R33 ในคิวส่วนตัว `nongkum_sports.result_submissions` เท่านั้น ผ่านเครื่องมือบริหาร; `status=review`, `received_via=chat`, `revision=1`, `evidence_ref` ชี้ภาพที่ผู้ใช้แนบในแชท, `source_ref` ผูก R33 active/fixture; ไม่ใส่คะแนนเพราะภาพไม่แสดงคะแนน.
2. ตรวจทวน fixture/ทีมคู่แรก/ผู้เข้ารอบ และความต่อเนื่องของผัง; ถ้าขัดแย้ง หยุดเฉพาะสายนั้น.
3. ให้ **ผู้มีสิทธิ์รับรอง** ตรวจภาพ/คะแนน/คู่แข่งและยืนยันในคิวผู้ตรวจ; ห้าม AI รับรองแทนมนุษย์หรือเขียนตรงลง `public.nongkum_published_results`.
4. หลังรับรอง ให้ตรวจผลสาธารณะใน `public.nongkum_published_results` และหน้าเว็บ `results.html` (เว็บใช้ bridge เฉพาะผลรับรอง ไม่ใช่การ Merge PR).
5. ซิงก์แก้ผังชาย 10 ปีด้วยข้อมูลที่ผู้จัดรับรองเท่านั้น; ตรวจ Supabase ↔ GitHub `main` ↔ สูจิบัตร และรักษา revision กับต้นฉบับ.

## ข้อจำกัดและหลักฐานที่ค้าง
- ภาพถ่ายกระดานเป็นหลักฐานจากผู้ใช้ ยังไม่ได้แนบเอกสารลงนาม/ชื่อผู้รับรอง; ไม่อ้างว่าประกาศผลทางการได้.
- ต้นฉบับภาพยังอยู่ในบทสนทนา ไม่ได้คัดลอกไปยังแหล่งสาธารณะและไม่เปิดเผยเด็ก/ข้อมูลส่วนตัว.
- การเปลี่ยนฐานคิวรอตรวจไม่ทำให้เว็บสาธารณะเปลี่ยน. PR นี้เป็นบันทึกการตรวจและข้อมูลร่าง ไม่ใช่การเปิดผลทางการ.
- ต้องตรวจเว็บภายนอกจริงหลังรับรอง และไม่อ้าง `Merge` ว่าเท่ากับเผยแพร่.

สถานะ: **ร่างแผนและผลตรวจ**, รอผู้รับรองผล; ห้าม Merge โดยพลการ.
