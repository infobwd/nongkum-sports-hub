# R39-C/D — คู่มือรูปภาพกิจกรรมที่ผ่านการตรวจและการเผยแพร่
สถานะ: กระบวนการและตัวอ่านรูปสาธารณะพัฒนาในสาขา R39; **ไม่ได้เปิดระบบอัปโหลดสาธารณะ** และ **ยังไม่มีรูปกิจกรรมที่ผ่านการตรวจรับใน manifest**

## พื้นที่ที่มีอยู่แล้ว
- โฟลเดอร์ Drive ส่วนตัว [ภาพถ่ายประจำสนาม](https://drive.google.com/drive/folders/1x5JpwQmqJaSOSoo3oOL8Fs3KwJV6yjpY) แยกตามวันและชนิดกีฬา; วันที่ 16 พฤศจิกายน 2569 มีโฟลเดอร์ กรีฑา เปตอง ยิงจุดโทษ
- [รูปภาพประกอบสูจิบัตร](https://drive.google.com/drive/folders/1rI-X5ol9VcJmNPaqwu-y3XEcnXTuuG8n) มี `03_ภาพกีฬา` ตามชนิดกีฬา
- ไม่ย้ายไฟล์ต้นฉบับ ไม่เปิดสิทธิ์ลิงก์ Drive เป็นสาธารณะ และไม่เอาภาพใบคะแนน/ลายเซ็นขึ้นเว็บไซต์

## วิธีทำสำหรับเจ้าหน้าที่
1. ผู้ได้รับสิทธิ์เข้าถึง Drive อัปโหลดภาพไว้ในโฟลเดอร์วันที่และชนิดกีฬาของกิจกรรม — ไม่อัปโหลดผ่านเว็บสาธารณะ
2. ผู้คัดเลือกตรวจรูปจริง: กิจกรรมตรงรายการ, ไม่มีข้อมูลส่วนบุคคล/เอกสารลับ, มีการอนุญาตใช้ภาพนักเรียนและผู้เกี่ยวข้อง, ไม่มีบุคคลที่ไม่ได้รับอนุญาต
3. ผู้รับผิดชอบบันทึกหลักฐานการอนุญาตและไฟล์ต้นฉบับเฉพาะในพื้นที่ Drive ส่วนตัว; หากหลักฐานไม่ครบ **ห้ามส่งเผยแพร่**
4. เจ้าหน้าที่สร้าง WebP อนุพันธ์คุณภาพเหมาะสม (.webp ไม่เกิน 350 KB) ไม่ติด EXIF/ตำแหน่ง/ข้อมูลส่วนตัว, ตั้งชื่อไฟล์ `[a-z0-9-]+` และวางใน `assets/activity-approved/`
5. เพิ่มรายการลง `data/public-activity-media.json` หลังผ่านการตรวจแล้วเท่านั้น โดยใช้รหัส fixture/event ที่ตรงกับตาราง 236 รายการ (ไม่เดาจากชื่อไฟล์):
   ```json
   {
     "event_id": "EXACT_SCHEDULE_ID",
     "sport_id": "athletics",
     "division": "EXACT_DIVISION",
     "src": "assets/activity-approved/approved-activity-photo.webp",
     "caption": "ภาพการแข่งขันกรีฑา",
     "revision": 1,
     "status": "approved",
     "consent_checked": true
   }
   ```
   ตัวอย่างข้างต้นเป็น **รูปแบบข้อมูลเท่านั้น** ไม่ใช่ภาพหรือรายการที่รับรองแล้ว
6. เปิด PR ให้ผู้รับผิดชอบตรวจภาพจริงและเอกสารอนุญาตที่เก็บส่วนตัว, เก็บประวัติแก้ไข, รัน `node scripts/r39/test-activity-media.mjs`, รออนุญาต Merge แล้วตรวจมือถือ Safari/Chrome/LINE อีกครั้ง

## ส่วนสาธารณะที่พัฒนาแล้ว
- `js/activity-media-r39.js` อ่านไฟล์ manifest ซึ่งมีแต่ภาพที่ผู้จัดคัดแล้ว และตรวจ `status=approved`, `consent_checked=true`, revision และ path แบบ WebP จากโฟลเดอร์ที่กำหนดเท่านั้น
- `js/results-renderers.js` ตรวจ `event_id || fixture_id` ตรงกับ sport+division อีกครั้ง จึงแสดงภาพบนการ์ดผลที่รับรอง; ไม่มีรายการผ่านตรวจให้ใช้ภาพสัญลักษณ์ WebP R38 ตามเดิม
- ตัวตรวจ `scripts/r39/test-activity-media.mjs` ปฏิเสธ path ภายนอก/Drive/ข้อมูลที่ไม่ครบ, ภาพเกิน 350 KB และรูปที่ไม่มี fixture ID ตรงจริง

## ข้อจำกัดและงานต่อ
- การเลือกภาพจาก Drive, การขออนุมัติ, การจัดการเอกสารความยินยอมและสร้าง WebP ยังเป็นกระบวนการของเจ้าหน้าที่ ไม่ใช่ปุ่มอัปโหลดออนไลน์ที่เปิดให้ทุกคน
- ยังไม่มีแหล่งภาพจริงที่ตรวจความยินยอมและประกาศอนุญาตเผยแพร่แล้ว จึง **ไม่มีการเผยแพร่ภาพนักกีฬาใน PR นี้**
- R39-D ภาพแชร์ OG จะคงภาพผลรับรองแบบกราฟิกที่ปลอดภัยก่อน; จะผสานภาพกิจกรรมเฉพาะหลังมีรูปที่อนุมัติและ QA 1200x630 แล้วเท่านั้น
- ไม่สร้าง backend สำหรับอัปโหลดโดยใช้ service role ในหน้าเว็บสาธารณะ; ถ้าพัฒนาระบบเว็บสำหรับเจ้าหน้าที่ภายหลัง ให้แยกบทบาทผู้ส่งภาพ/ผู้อนุมัติและเก็บหลักฐานที่จำกัดสิทธิ์
