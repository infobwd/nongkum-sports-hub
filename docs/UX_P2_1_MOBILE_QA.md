# UX-P2.1 — Mobile-first โปรแกรมสูจิบัตรกีฬา (ข้อมูลร่าง)

สถานะ: IMPLEMENTED ON FEATURE BRANCH / QA IN PROGRESS  
ฐานข้อมูลอ้างอิง: `data/draft-schedule.json` จาก PDF 40 หน้า  
ขอบเขต: **ปรับการนำเสนอเท่านั้น ไม่แก้ข้อมูลกีฬา วัน เวลา สนาม หรือการอนุมัติ**

## ปัญหาที่แก้

1. ผู้ปกครอง/ครูเลือกโรงเรียนแล้วการ์ดกรีฑายังแสดงรายชื่อทุกลู่ ทำให้สูงเกินจำเป็น
2. ส่วนหัวและคำเตือนเดิมใช้พื้นที่ส่วนต้นของจอมาก ก่อนเห็นตัวกรอง
3. ข้อมูล `วัน/เวลา/สนามรอยืนยัน` ซ้ำหลายป้ายต่อการ์ด
4. โปรแกรมมี 236 รายการ หากแสดงทันทีทั้งหมดบนมือถือจะต้องเลื่อนยาว
5. กลุ่มตัวกรองเดิมมีเพียงโรงเรียนและกีฬา ไม่มีช่วงชั้น
6. ส่วนผู้จัดยังอธิบายว่า “เตรียมระบบ Google Sheets” ทั้งที่สร้าง P2 แล้ว

## ปรับหน้าเว็บจริง

- หัวเว็บสั้น: ชื่องาน, สถานะร่าง, คำอธิบาย 1 บรรทัด; ช่องเลือกโรงเรียนมาก่อนคำเตือนยาว
- คง `ข้อมูลร่าง`, `ยังไม่เป็นทางการ` และคำเตือนห้ามใช้เป็นกำหนดการแข่งขันอย่างชัดเจน
- เพิ่มช่วงชั้น `ทุกช่วงชั้น` / `ก่อนเรียน / ปฐมวัย` / `ประถม` / `มัธยม`, แยกจากชนิดกีฬา
- ชิปกีฬาแนวนอนพร้อมข้อความ `เลื่อนเพื่อดูกีฬาอื่น →`
- การ์ดกรีฑาแสดงเฉพาะลู่ของโรงเรียนที่ผู้ใช้เลือก; ชื่อใน PDF ยังแสดงตรงตามต้นฉบับ
- ไม่มีโรงเรียนที่เลือก: แสดงจำนวนลู่ในต้นฉบับแทนรายชื่อทั้งหมด
- ใช้ `<details><summary>ดูทุกลู่ (N)</summary>` เพื่อเปิดดูครบเมื่อจำเป็น รวมหมายเหตุลู่ว่างจากต้นฉบับ
- แบ่งผลลัพธ์เป็นกลุ่มตามกีฬา และแสดงครั้งละ 12 รายการ พร้อมปุ่ม `แสดงเพิ่มอีก N รายการ` เพื่อไม่ให้หน้าเว็บยาวตั้งแต่แรก
- แถบสถานะย่อ: เมื่อวันเวลา/สนามล้วนว่างให้แสดง `วัน · เวลา · สนาม รอยืนยัน` รวมป้ายเดียว
- หาก PDF มีเวลา/สนาม จะแสดง `เวลาใน PDF` / `สนาม ... (ตาม PDF)` แยกจากคำว่า `วันรอยืนยัน`
- ส่วนผู้จัดยุบในแถบรายละเอียด พร้อมลิงก์คู่มือ `P2_SHEETS_WORKFLOW.md`, QA และแผน
- คง `source_page`, เลขคู่/รายการซ้ำตาม PDF (35,48) และชื่อศูนย์ฯ โดยไม่สมมติ ID โรงเรียน
- รองรับพารามิเตอร์แชร์ URL `school`, `sport`, `level` และจดจำโรงเรียนในเครื่องตามเดิม
- ป้าย `เรียงตามสูจิบัตรต้นฉบับ ไม่ใช่ลำดับเวลาแข่งที่ได้รับการรับรอง`

## สถานะของข้อมูลและข้อจำกัด

- เว็บยังอ่าน `data/draft-schedule.json` ซึ่งมี **186 คู่ + 50 กรีฑา** ทั้งหมดสถานะ `draft`
- ไม่ได้เชื่อม Google Sheets P2 กับหน้าเว็บ
- ทุก `date` ยังเป็น `null`; คงข้อมูลเวลา/สนามเฉพาะที่ PDF ระบุ
- รายการ `ก่อนเรียน (ศูนย์ฯ)` ใช้ป้ายศูนย์ฯ เดิม ไม่แสดงว่าเป็นรายการของโรงเรียนเมื่อเลือกโรงเรียน
- การกรองระดับ `ประถม` อิงข้อความช่วงอายุ 8/10/12 ปีจากข้อมูลต้นฉบับ ไม่แทนการรับรองรุ่นการแข่งขัน
- เมื่อเลือกโรงเรียนที่ไม่ปรากฏในคู่รอบถัดไป เพราะต้นฉบับยังระบุ `ผู้ชนะคู่ที่...` เท่านั้น ระบบจะไม่คาดเดาว่าโรงเรียนนั้นเข้ารอบ
- ปรับ UX เท่านั้น ไม่มีฟังก์ชันบันทึก/ประกาศผลการแข่งขัน

## เกณฑ์ตรวจรับอัตโนมัติ

- [ ] `node scripts/validate-data.mjs` — ชุด P1 ยังผ่าน
- [ ] `node scripts/p2/test-approval.mjs` — P2 approval gate ยังผ่าน
- [ ] `node scripts/ux/test-mobile-ui.mjs` — รันสคริปต์หน้าเว็บกับ JSON จริงทั้ง 236 รายการใน DOM mock:
  - กรองโรงเรียน/กีฬา/ช่วงชั้นถูกต้อง
  - กรีฑาของโรงเรียนแสดงเฉพาะลู่ตนเองก่อนและเปิดข้อมูลครบได้
  - เริ่มแสดง 12 รายการ แล้วเพิ่มครั้งละ 12
  - ป้องกัน HTML injection จากข้อความต้นฉบับ
  - ตัวกรองไม่รู้จักไม่ทำให้ข้อมูลถูกซ่อนโดยไม่แจ้ง
  - ปฏิเสธการแสดงข้อมูลที่ไม่ผ่านสถานะ prototype/draft
  - ตรวจ breakpoint หน้าแสดงผลมือถือหนึ่งคอลัมน์

## การตรวจด้วยมือที่แนะนำ

**ต้องทำบนอุปกรณ์จริงก่อนถือว่าผ่าน Visual QA:**

- [ ] iPhone Safari กว้างประมาณ 320–390px: ส่วนหัว กระดุมช่วงชั้น และเลือกโรงเรียนไม่ล้นจอ
- [ ] Android Chrome: เลื่อนชิปกีฬาแนวนอนได้และการกด `ดูทุกลู่` ใช้งานได้
- [ ] เลือกโรงเรียนบ้านวังด้ง + กรีฑา + 12 ปี: เห็นลู่ของตนเองและกดดูทุกลู่
- [ ] ไม่เลือกโรงเรียน: การ์ดกรีฑาสั้น และเปิดทุกลู่ได้
- [ ] เปลี่ยนโรงเรียน/ช่วงชั้นแล้วจำนวนผลค้นหาและพารามิเตอร์ URL เปลี่ยนถูกต้อง
- [ ] กด `แสดงเพิ่ม` จนสุด ผลลัพธ์ครบ ไม่มีข้ามหรือซ้ำจากการแบ่งหน้า
- [ ] ตรวจโหมดขยายตัวอักษร 125–200%, VoiceOver/TalkBack, คอนทราสต์ และแป้นพิมพ์
- [ ] ตรวจการใช้งานเน็ตช้า/โหลด JSON ไม่ได้
