# R15-A — ตรวจรับหน้าอันดับแยก (UI shell; ยังไม่มีอันดับจริง)

สถานะ: R15-A implementation · 5 พฤศจิกายน 2569 · อ้างอิง [แผน R15](R15_RESULTS_STANDINGS_PHOTO_JSON_PLAN.md).

## สิ่งที่ทำ
- เพิ่ม [หน้าตารางอันดับ](../standings.html) แยก HTML/CSS/JS ไม่เพิ่มขนาด `js/results.js` ยกเว้นการอัปเดตลิงก์แท็บย่อย.
- [หน้าผลการแข่งขัน](../results.html) เพิ่มแท็บย่อย **ผลรายคู่ | ตารางอันดับ**; บนมือถือยังมีเมนูล่าง **ตารางแข่ง | ผลแข่งขัน** เพียงสองรายการ.
- กรองโรงเรียน กีฬา ช่วงชั้น แล้วกลับไปมาระหว่างผลรายคู่และตารางอันดับด้วยพารามิเตอร์ `school`, `sport`, `level` ที่คงเดิม.
- หน้าอันดับโหลด `data/public-results.json` โดยตรงพร้อม `cache: no-store` และรีเฟรชทุก 5 นาทีเมื่อมองเห็นหน้า (ไม่โหลด JSON สูจิบัตร 237 รายการ).
- ผลรับรอง 0 รายการ: แสดงหน้าเปล่าตรงตามข้อมูล; ถ้าอนาคตมี approved ให้บอก **รอรับรองเกณฑ์จัดอันดับ** ไม่คำนวณคะแนนก่อน R15-B.
- รักษา loading skeleton, ปุ่มลองอีกครั้ง, error state, เก็บข้อมูลล่าสุดเมื่อการรีเฟรชล้มเหลว.
- **ไม่เพิ่ม** `data/public-standings.json`, engine, rules สมมติ หรือข้อมูลผลแข่งขันจริง.

## Regression และการตรวจรับจริง

1. เปิด `results.html` กด “ตารางอันดับ”: ไป `standings.html` และเลือกแท็บย่อยถูกต้อง.
2. เปิด `results.html?school=wangdong&sport=football&level=primary`, กดตารางอันดับ → ลิงก์ปลายทางคงทุกตัวกรอง. เปลี่ยนตัวกรองแล้วกด “ผลรายคู่” → ตัวกรองยังตรง.
3. iPhone Safari / LINE / Android: เมนูล่างยังสองแท็บ กด “ผลแข่ง” จากหน้าอันดับต้องกลับหน้า `results.html`; หัวไม่ถูกแถบสถานะบังและเนื้อหาไม่ทับเมนูล่าง.
4. ณ วันตรวจรับ data/public-results.json ว่าง (approved 0): ห้ามแสดงอันดับ คะแนนสมมติ เหรียญ หรือชื่อเด็ก.
5. กดรีเฟรช/ตัดเน็ต/กลับมาออนไลน์: แยก “ยังไม่มีผล” กับ “โหลดข้อมูลไม่สำเร็จ” และข้อมูลเดิมยังคงอยู่เมื่อรีเฟรชผิดพลาด.
6. หน้า results เดิมยังเปิดลิงก์ผลตรงรายการ `?result=`, การกรอง และแชร์ได้เหมือนเดิม.
7. ชุดทดสอบ: `node scripts/results/test-standings-r15a.mjs` + R2, R6, R9 regressions.

## Gate ถัดไป
R15-B ต้องรับรองการคิดคะแนน/ตัดอันดับและแยก 15 คู่ฟุตบอลพบกันหมดออกจาก 2 คู่รอบต่อไปก่อนเริ่มสร้าง standings engine/snapshot. ไม่มีการอัปเดต JSON ผลจริงใน R15-A.
