## 3. ลำดับงานและจุดตรวจ
1. **PLAN:** commit ไฟล์นี้ลง branch แยกก่อนแก้ระบบเว็บ; ตรวจ source revisions/PR ไฟล์ชนกัน
2. **DATA:** จัดทะเบียนข้อสังเกตฉบับอ่านอย่างเดียว กำหนดรหัสคงที่ แหล่งอ้างอิง หน้า PDF, กีฬา, หมวด/ความสำคัญ, คำถามที่ต้องตัดสิน, สถานะ, หลักฐาน. รายการจาก `source_qa` ต้องอ้างรหัส/คำอธิบายต้นทางจริงและตรวจ revision เมื่อโหลด. รายการจากแผนงานอื่นต้องมีที่มาที่เปิดได้
3. **UI:** สร้างหน้าใหม่มือถือเป็นหลัก; สรุปจำนวน *กลุ่มประเด็นในทะเบียน* (ไม่นับ 70 flags/486 anchors เป็นข้อผิดพลาด), ค้นหา/กรองเร่งด่วน-ประเภท-สถานะ, อ่านประเด็น/ผลกระทบ/สิ่งที่ต้องยืนยัน, ปุ่มเปิด PDF V2 หรือเล่ม 155 และคัดลอกข้อความส่งผู้จัด. มี loading, error, empty state, safe-area, 44px touch target, no-tech jargon, ไม่ต้องล็อกอินเพื่ออ่าน
4. **LINKS:** เพิ่มลิงก์หน้าใหม่ใน `booklets.html` และ `booklet-comparison.html` โดยไม่เปลี่ยนระบบอ่าน PDF เดิม
5. **VERIFY:** เพิ่มการตรวจทะเบียนเทียบ `source_qa`/source hash, unique IDs/valid pages/valid status, ห้ามมี `approved` จากข้อมูลร่าง, ห้ามมีผลคะแนนหรือข้อมูลรายบุคคล, regression 236 active / 250 committee / 486 anchors / 155 pages ไม่แก้; ตรวจ HTML/JS ด้วย Node/CI; manual Safari/LINE/Android ยังต้องแยกจริง
6. **PR → MERGE:** ทดสอบ/ตรวจ source และ no-conflict; merge ด้วยคำอนุญาตผู้ใช้ในแชทนี้เมื่อ gates ผ่าน; ตรวจ readback main และลิงก์ Pages. **MERGED ≠ DEVICE ACCEPTED ≠ OFFICIALLY APPROVED**
