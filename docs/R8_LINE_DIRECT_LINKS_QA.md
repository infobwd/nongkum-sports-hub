# R8 — LINE Deep Links และลิงก์สั้นเฉพาะคู่แข่งขัน

สถานะ: R8 implemented, ต้องตรวจการเปิดจริงด้วย LINE iOS/Android หลัง GitHub Pages Deploy  
ชื่อกิจกรรม: **มิตรภาพเกม 2569**  
Scope: เว็บไซต์สาธารณะ ไม่เปลี่ยนคะแนน/คู่แข่งขัน ไม่เชื่อมข้อมูลร่างจาก Google Sheets โดยตรง

## ปัญหาต้นทางจากภาพ

ผู้ปกครองแตะลิงก์ที่ LINE ส่งมา เช่น

`index.html?fixture=football-p07-12-%E0%B8%9B%E0%B8%B5-%E0%B8%8A%E0%B8%B2%E0%B8%A2-009`

รหัส URL นี้ถอดกลับเป็น `football-p07-12-ปี-ชาย-009` ที่มีอยู่จริงในข้อมูล PDF: ฟุตบอล 12 ปี ชาย คู่ที่ 9 หนองกระทุ่ม VS วังด้ง หน้า 7

พฤติกรรมเดิม: หน้าโปรแกรมพยายามกรองแล้วเรียก `scrollIntoView()` ภายหลังการโหลด JSON; หาก LINE WebView ไม่เก็บ scroll position หรือรายการอยู่หลัง 12 รายการแรก จะดูเหมือนเปิดหน้ารวม

## สิ่งที่พัฒนา

### 1. ลิงก์เก่าที่มี ?fixture= ต้องเปิดตรงคู่

- เพิ่ม `#sharedFixture` อยู่ **ก่อน** ส่วนค้นหาใน `index.html`
- เมื่อมี `?fixture=` จะซ่อนหน้ารวม แล้วเปิดการ์ดเป้าหมายที่จุดบนสุดทันทีหลังอ่านข้อมูลจาก `data/draft-schedule.json`
- แสดงกีฬา รุ่น คู่แข่งขัน วัน/เวลา/สนามตามสถานะจริงจากไฟล์ และรายละเอียดต้นฉบับ
- ไม่ขึ้นกับอันดับรายการ 1–12 หรือการกรองโรงเรียนที่ผู้รับเคยตั้งไว้
- หากไม่พบรหัส ต้องแสดงข้อความ `ไม่พบคู่แข่งขันที่แชร์มา` **ไม่กลับหน้ารวมเงียบ ๆ**
- มีปุ่ม `ดูตารางการแข่งขันทั้งหมด` สำหรับกลับไปหน้าค้นหาโดยสมัครใจ
- ข้อมูลร่างยังมีป้ายเตือน ไม่กลายเป็นผลรับรอง

### 2. ลิงก์ใหม่สั้นและ LINE Preview ระดับรายคู่

เพิ่มหน้า HTML แบบ static แต่ละรายการทั้ง **236 หน้า** ภายใต้:

`https://infobwd.github.io/nongkum-sports-hub/m/<shortcode>/`

รหัสใหม่เป็น `f` + hexadecimal 8 ตัว (ASCII ล้วน) จาก FNV-1a ของ `fixture_id` เดิม
- ตัวอย่างฟุตบอลคู่ที่ 9: `m/f9ba2a496/`
- ลิงก์สั้นคงที่ตราบใดที่ `fixture_id` ไม่เปลี่ยน; สคริปต์ตรวจการชนกันของรหัส
- ทุกหน้า HTML สร้างด้วยข้อมูลจริงจาก `data/draft-schedule.json` มี `og:title`, `og:description`, `og:url`, `og:site_name`, `og:locale`, `twitter:card`, canonical URL
- LINE crawler อ่าน OG จาก HTML ได้โดยไม่ต้องรัน JavaScript: ชื่อกีฬา รุ่น ชื่อคู่ และ **ข้อมูลร่าง**
- หน้าแสดงคู่แข่งขันทันทีโดยไม่ต้องโหลด JSON 236 รายการก่อน และมีปุ่มไปยังรายละเอียดฉบับเต็ม `index.html?fixture=...`
- ไม่มีคะแนนผลสมมติหรือชื่อเด็ก/ข้อมูลส่วนตัวในหน้าแชร์
- ถ้า LINE ยังแสดงข้อความ preview เก่า ให้ลองแชร์ลิงก์สั้นใหม่และรอตรวจ cache ของ LINE; การมี OG metadata ไม่รับประกันว่าทุกเวอร์ชันของ LINE จะแสดงภาพ/ข้อความเหมือนกัน
- **ไม่มี og:image ที่เจาะจงรายคู่** ใน R8 เพราะยังไม่มีภาพที่ได้รับรองและไม่จำเป็นต่อการเปิดตรงคู่

### 3. การอัปเดตข้อมูล

ไฟล์ `data/share-index.json` เป็น mapping จากรหัสสั้นไปยัง `fixture_id` ใช้ตรวจสอบการไม่ซ้ำของลิงก์

เมื่อแก้ข้อมูลโปรแกรมในอนาคต:

```bash
node scripts/share/build-match-pages.mjs
node scripts/share/build-match-pages.mjs --check
```

ต้อง commit หน้าสั้นและ mapping ที่สร้างใหม่ร่วมกับ `data/draft-schedule.json`; CI จะบังคับตรวจ `--check` เพื่อป้องกัน Preview เก่าหรือสับสนกับข้อมูลล่าสุด

ลิงก์เก่าแบบ `?fixture=<เดิม>` ยังคงใช้ได้ ไม่เปลี่ยนคีย์และไม่ต้องตั้ง redirect

### 4. ผลการแข่งขันที่แชร์

`results.html?result=<id>` แสดงหน้าผลเฉพาะ ID ที่ **approved และเผยแพร่** ก่อนตัวกรองเช่นกัน
- ไม่พบ/ยังไม่รับรอง: มีข้อความ `ยังไม่มีผลการแข่งขันที่ผ่านการรับรองสำหรับลิงก์นี้`
- ไม่เผยแพร่ผล Draft/Review และไม่ใส่คะแนนตัวอย่างลงไฟล์ public
- ขณะทำ R8 ผลจริงที่เผยแพร่ยังเป็น **0**
- การสร้าง OG Preview แยกตามผลจริงจะพิจารณาเมื่อมีข้อมูลผลรับรองที่อนุญาตให้เผยแพร่ เพื่อไม่สร้างหน้าคะแนนที่ยังไม่มีหลักฐาน

## ตรวจด้วย LINE จริง

- [ ] LINE iPhone: ส่งลิงก์ใหม่ฟุตบอลคู่ที่ 9 → preview บอกฟุตบอล หนองกระทุ่ม–วังด้ง และข้อมูลร่าง
- [ ] แตะลิงก์ → เห็นคู่ที่ 9 ทันที ไม่ใช่หน้าค้นหารวม
- [ ] LINE Android: ลักษณะเดียวกัน ไม่มีการเลือกโรงเรียนเก่าเข้ามากรอง
- [ ] ส่งลิงก์เก่า `?fixture=...` → เปิดหน้ารายละเอียดตรงคู่เหมือนกัน
- [ ] ทดสอบรายการกรีฑา/เปตอง และคู่หลังลำดับ 12
- [ ] รหัสผิด → หน้าชี้แจงอย่างสุภาพ ไม่แสดงคู่ผิด
- [ ] ตรวจ URL และ OG ของหน้าแชร์ด้วยเครื่องมือทดสอบ metadata เมื่อ GitHub Pages Deploy แล้ว
- [ ] ทดสอบแชร์ผลเมื่อมี approved จริงในอนาคตเท่านั้น

ข้อจำกัดสำคัญ: GitHub Actions ตรวจข้อมูลและ HTML เท่านั้น ยังไม่ได้พิสูจน์ว่า LINE WebView/LINE crawler ของอุปกรณ์จริงแสดง Preview ตามคาด
