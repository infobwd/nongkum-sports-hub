- ไม่บันทึก Google Docs ID, Sheet ID หรือข้อมูลผู้ตรวจภายในลง repository สาธารณะ

## 3. หลักการออกแบบเอกสารฉบับสมบูรณ์

1. JSON ที่ผ่าน R11A review/reconciliation เท่านั้นจะเป็นแหล่งของตารางคู่แข่งขันและกรีฑา; Docs เป็น **generated view** ไม่ใช่ master อีกชุด
2. ทุกหน้ากำหนดการแข่งขันต้องอ้างถึง `revision`, สถานะ, วันที่สร้าง และรหัสรายการ/หน้า PDF; ช่วยให้เทียบกับเว็บและ Sheet ได้
3. ใช้ Google Docs native headings / tables และจัดเป็น A4 แยกชนิดกีฬา รุ่น รอบ คู่แข่งขัน กรีฑาและลู่ โดยคงชื่อ/หมายเลขจาก PDF และ `qa_flags`
4. แยกส่วนพิธีการ/คำสั่ง/บุคคลออกจากส่วน data-generated; ให้ผู้จัดตรวจหรือเติมจากแหล่งที่ยืนยันแล้ว
5. ข้อผิดพลาด/เลขซ้ำ/วันที่ปี 2568 ใน PDF จะไม่ถูกแก้แบบเดา; มีช่องแสดง `ต้องตรวจสอบ` จนมีมติ
6. การ export PDF/เผยแพร่ฉบับทางการอยู่ใน R11E หลังผู้จัดอนุมัติเท่านั้น; ยกเว้นตัวอย่างเพื่อทดสอบภายในที่ติดป้าย DRAFT

## 5. ข้อจำกัดและการรับส่งข้ามแชท

- **R11A** รับผิดชอบ JSON, schema, reconciliation, revision lock; R11C ไม่แก้ `data/*`
- **R11D** รับผิดชอบหน้าตรวจเว็บ; R11C ไม่แก้ HTML/CSS/JS ของเว็บ
- **R10** รับผิดชอบคิวประกาศสนาม; R11C ไม่อ่าน/เขียนชีทคิวหรือประกาศ
- **R11E** รับผิดชอบการ release และเผยแพร่เอกสารฉบับรับรอง
- งาน R11C อยู่ใน **Google Docs สำเนาใหม่** และ `docs/R11C_*` เท่านั้น ณ gate นี้
