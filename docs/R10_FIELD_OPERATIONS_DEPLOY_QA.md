# R10 — คู่มือติดตั้งและตรวจรับศูนย์ประกาศสนาม (Phase 2)

สถานะ: **CODE READY / LIVE WEB APP NOT DEPLOYED** · 4 พฤศจิกายน 2569  
อ้างอิงแผน: [R10 Field Operations Phase 2](R10_FIELD_OPERATIONS_PHASE2_PLAN.md)

## เป้าหมายและการแยกข้อมูล
- ใช้ **Google Sheets ภายในสำหรับกองอำนวยการโดยเฉพาะ**, แยกออกจาก P2 สูจิบัตร/ผลการแข่งขัน; ไม่มีการลิงก์ระหว่างข้อมูลคำขอกับ `06_ประกาศ` ของ P2 อัตโนมัติ
- โครงแท็บ (สร้างใน Google Drive แล้ว แต่ **URL/ID เป็นข้อมูลภายใน ไม่บันทึกใน repo public**):
  - `01_คิวประกาศ`: 16 คอลัมน์ เริ่ม `id, created_at, created_by, type, priority...`
  - `02_ประวัติประกาศ`: 8 คอลัมน์ เริ่ม `log_id, occurred_at, actor, request_id...`
- โปรแกรมภายในใช้ Google Apps Script **standalone project** เพื่อให้เจ้าหน้าที่ที่แก้ Sheet ไม่ได้รับสิทธิ์แก้ source code ของ Web App ด้วย
- คิวนี้เป็น **งานประสานภายในสนาม** เท่านั้น: ไม่ใช่ประกาศทางการ ไม่เผยแพร่ขึ้นเว็บสาธารณะ ไม่ใช้แทนมติการเปลี่ยนวัน/เวลา/สนาม

## Code ที่พร้อมติดตั้ง
- `apps-script/Announcer.gs` — server-side authentication, operations queue, templates, locking, transition gate และประวัติการดำเนินงาน
- `apps-script/Announcer.html` — responsive UI: กองอำนวยการ/มือถือ, สร้างคำขอ, กรองคิว, คัดลอกข้อความ, ตรวจพร้อม/ประกาศแล้ว/ยกเลิก, ประวัติ 100 รายการ, รีเฟรชทุก 25 วินาทีเมื่ออยู่บนหน้าจอ
- `scripts/ops/test-field-console-r10.mjs` — simulated Apps Script regression

## ขั้นตอนติดตั้งด้วยบัญชีเจ้าของ (ยังต้องทำใน Google UI)

1. เปิด Google Sheets ภายในที่เจ้าของสร้างไว้ แล้วจด **Spreadsheet ID** จาก URL (เก็บเป็นความลับภายใน ไม่ commit GitHub)
2. เข้า [script.google.com](https://script.google.com/) โดยบัญชีผู้ดูแล เลือก **New project** → ชื่อ `มิตรภาพเกม 2569 — ศูนย์ประกาศสนาม`
3. วาง source `Announcer.gs` เป็นไฟล์ Script ชื่อ **Announcer.gs**; เพิ่มไฟล์ HTML ชื่อ **Announcer** (ในตัวแก้ไขจะเห็น `Announcer.html`) แล้ววาง source `Announcer.html` จาก repo; **ไม่ต้องนำ `Code.gs` หรือ `Results.gs` ของ P2 มาผสม**
4. ไปที่ Project Settings → **Script properties** สร้างค่า:
   - `NONGKUM_OPS_SPREADSHEET_ID` = ID ของ Google Sheet ภายใน (ห้ามตั้งเป็น sheet P2)
   - `NONGKUM_OPS_ADMIN_EMAILS` = อีเมลผู้ดูแล (อย่างน้อย 1 บัญชี)
   - `NONGKUM_ANNOUNCER_EMAILS` = อีเมลผู้บรรยายที่อนุญาตให้เปลี่ยนสถานะประกาศ
   - `NONGKUM_COORDINATOR_EMAILS` = อีเมลผู้ประสานสนามที่ส่งคำขอได้ (คั่นด้วยเครื่องหมาย comma)
5. แชร์ **Google Sheet ภายในเท่านั้น** เป็น Editor ให้บัญชีที่ใช้ Web App (เฉพาะผู้ไว้วางใจ); **ไม่แชร์ Apps Script project เป็น Editor** และ **ไม่แชร์ P2 สูจิบัตรเป็น Editor เพิ่มเพียงเพื่อใช้คิวนี้**
6. ใน Apps Script เลือกฟังก์ชัน `nkOpsSetup` กด Run ด้วยบัญชีที่อยู่ใน `NONGKUM_OPS_ADMIN_EMAILS`, ตรวจสอบสิทธิ์ OAuth ตามข้อความ Google, ผลลัพธ์ต้องได้ `ok:true` (สองแท็บเดิมไม่ควรถูกลบหรือถูกกรอกข้อมูลตัวอย่าง)
7. Deploy → New deployment → เลือกประเภท **Web app**
   - **Execute as**: `User accessing the web app` (ห้ามใช้ `Me` สำหรับการพิสูจน์สิทธิ์ด้วย Session)
   - **Who has access**: เฉพาะบัญชี Google ตามรูปแบบที่ผู้ดูแลอนุญาต (การจำกัดที่ระดับ Web App ยังต้องใช้ allowlist server-side)
   - บัญชีผู้ใช้แต่ละคนต้องยอมรับสิทธิ์ของ Web App ตามที่ Google แสดง และต้องเข้าถึง Sheet ภายในได้
8. เปิด URL /exec จากมือถือและคอมด้วยบัญชีเจ้าหน้าที่จริง; ทดลองด้วยบัญชีที่ไม่อยู่ใน allowlist ซึ่งต้องเข้าไม่ได้. **อย่านำ URL นี้ใส่เว็บ GitHub Pages จนกว่าผู้ดูแลจะตัดสินใจเรื่องการเปิดเผยลิงก์**
9. เก็บ URL /exec ภายในกลุ่มเจ้าหน้าที่ที่ได้รับอนุญาตเท่านั้น และปิดสิทธิ์หลังจบงานเมื่อไม่จำเป็น

### ปัญหาที่อาจพบ
- หาก Session ไม่คืนอีเมล (บางบัญชี/นโยบาย Google): ระบบจะ **ปฏิเสธ** ไม่ bypass allowlist; ตรวจบัญชีและการตั้งค่า deployment
- หากกดเปิดได้แต่แก้คิวไม่ได้: ตรวจ Editor permission บน **Sheet ภายใน** และให้ผู้ใช้ยืนยัน OAuth; การแชร์แค่ Web App ไม่พอสำหรับ mode execute-as-user
- หากไม่พบแท็บหรือ schema ผิด: ห้ามเขียนทับ; ตรวจ header ทั้ง 16 / 8 คอลัมน์และรัน `nkOpsSetup` โดย admin
- หากกดจากหลายเครื่อง: ระบบป้องกัน stale transition ด้วย `expected_version`; ให้รีเฟรชเมื่อแจ้งว่าอีกเครื่องแก้ไปแล้ว
- หากระบบโหลดคิวไม่ขึ้น: ผู้บรรยายยังใช้ไมค์/วิทยุสื่อสารได้ตามปกติ; อย่าอาศัยระบบเพียงช่องทางเดียวสำหรับกรณีฉุกเฉิน
- หากเพิ่มประกาศแล้วไม่พบ ให้กดรีเฟรชและตรวจสอบสถานะการเชื่อมต่อ (แสดงเวลาตรวจล่าสุด); ระบบนี้ **ไม่ใช่ push real-time**

## ขั้นตอนการทำงานจริง
1. ผู้ประสานสนามเปิดมือถือ → เลือก **เรียกนักกีฬา / ตามกรรมการ / ประชาสัมพันธ์** → กรอกข้อมูลที่ตรวจสอบแล้ว → ดู Preview → ส่งเข้าคิว `pending`
2. กองอำนวยการเลือกคิว ตรวจข้อความ/สนาม/ทีมกับผู้รับผิดชอบ → กด **ตรวจแล้ว · พร้อมประกาศ** (`ready`)
3. อ่านข้อความผ่านไมโครโฟนด้วยคน (ไม่ Auto-TTS) → กด **อ่านออกไมค์แล้ว** (`announced`) ระบบบันทึกเวลาและผู้ดำเนินการ
4. หากคำขอไม่ถูกต้อง ให้ผู้บรรยายกด **ยกเลิกคำขอ** (`cancelled`) แล้วให้ผู้ประสานสร้างคำขอใหม่แทนการแก้ประวัติย้อนหลัง
5. กองอำนวยการสามารถดูคิวประกาศทั้งหมดและประวัติ 100 รายการล่าสุด; เปิดค้างไว้อัปเดตแบบ polling 25 วินาทีเมื่อหน้าแสดงอยู่

## ความเสี่ยง/ข้อจำกัด
- ผู้มีสิทธิ์ Editor บน Google Sheet ภายในอาจแก้แถวโดยตรงได้ ดังนั้นประวัติเป็น **operational audit** ไม่ใช่ immutable audit หรือหลักฐานพิสูจน์ตัวบุคคลเชิงกฎหมาย
- UI ใช้ `textContent` กับทุกข้อมูลจากผู้ใช้ ไม่มี HTML injection; ข้อความเป็น plain text และต้องตรวจทานด้วยคนก่อนอ่านผ่านไมค์
- ต้องให้ผู้รับผิดชอบควบคุมการเปิดเผยข้อมูล ข้อความทั่วไปอาจมีความละเอียดอ่อน จึงห้ามใส่ชื่อ/เบอร์เด็ก
- โปรดทดสอบ quota และจำนวนบัญชีผู้ใช้จริงก่อนแข่ง; หากจำนวนคำขอเกิน 5,000 ระบบปิดการเพิ่มและให้ผู้ดูแลสำรอง/จัดเก็บข้อมูลก่อน
