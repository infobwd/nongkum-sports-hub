# R12B — ขั้นตอนรับภาพรายชื่อนักกีฬากระดาษเข้าสู่ JSON ส่วนตัว (ไม่มีหน้าลงทะเบียน)

**สถานะ: INTAKE READY / ยังไม่มีรายชื่อนักกีฬาจริงและยังไม่เริ่มวิเคราะห์รายบุคคล** · 4 พฤศจิกายน 2569  
**อ้างอิง:** [แผน R12](R12_ATHLETE_DOCUMENT_TO_JSON_SCHEDULE_CONFLICT_PLAN.md) และ [ผลคัดกรอง R12A](R12A_SCHOOL_TIME_RISK_REPORT_2569.md)

## แนวทางที่ล็อกแล้ว

- โรงเรียนส่งรายชื่อนักกีฬากระดาษตามวิธีเดิม ไม่ต้องสมัคร/กรอกฟอร์มออนไลน์ใหม่
- ผู้จัดส่งภาพเอกสารผ่านแชทที่ได้รับอนุญาตให้ประมวลผลข้อมูลส่วนบุคคล; AI ถอดเฉพาะข้อมูลจำเป็น, เจ้าหน้าที่ตรวจทานก่อนใช้วิเคราะห์
- สร้าง **โฟลเดอร์ใน My Drive ของบัญชีเจ้าของ** สำหรับ R12B แล้ว และตรวจ permission ณ วันที่สร้างว่า `shared=false`, สิทธิ์ **owner-only**, ไม่อยู่ Shared Drive (ไม่ใส่ ID/URL ของโฟลเดอร์ภายในลง Repository สาธารณะ)
- หากต่อไปต้องการ JSON ใน GitHub จริง ให้สร้าง **Private Repository ต่างหากพร้อมตรวจสมาชิกและการเก็บรักษา** ก่อน commit; โครงการ public `infobwd/nongkum-sports-hub` เก็บได้เฉพาะ schema/รายงาน aggregate ที่ไม่ระบุตัวนักเรียน

## เช็กลิสต์เมื่อได้รับภาพจากโรงเรียน

1. บันทึกโรงเรียน, ชนิดกีฬา, รุ่น, จำนวนหน้า, วันที่ได้รับ และรหัสเอกสารภายใน; ไม่ต้องเปิดเผยชื่อในรายงานสาธารณะ
2. ตรวจว่าภาพไม่ขาดขอบ ตัวอักษรอ่านได้ เห็นชื่อรายการและผู้เล่นครบหน้า; ถ้าภาพไม่ชัดทำเครื่องหมาย `needs_review` ไม่เดา
3. AI ถอด `name_raw`, โรงเรียน, กีฬา, รุ่น, บทบาทผู้เล่น/ตัวสำรอง, รายการวิ่ง/ลู่ถ้าระบุ, และ `source_ref` หน้า/แถวใน **JSON ภายใน**
4. ตรวจทุกชื่อกับกระดาษก่อนยืนยัน; ถ้าพบชื่อสะกดต่างกันหรือชื่อซ้ำในหลายกีฬา ต้องให้ผู้มีสิทธิ์ยืนยันว่าเป็นคนเดียวกันจึงกำหนด `athlete_id` เดียว
5. กีฬาประเภททีมผูก roster กับทีม/รุ่น แล้วโยงทุกคู่ที่ทีมอาจลง; รอบถัดไปที่ยังไม่รู้ผู้ชนะให้เป็น `conditional`; กรีฑาเชื่อมรหัสรายการ/ลู่แยก
6. ยืนยัน coverage `received / extracted / school_checked / accepted_for_analysis` รายโรงเรียน, ระบุจำนวนข้อมูลขาดและชื่อที่รอตรวจ (แสดงเฉพาะในระบบ private)
7. นำข้อมูลที่ยืนยันแล้วไปตรวจตาราง R12C. **ส่งเข้าพื้นที่ public เฉพาะผลรวมไม่ระบุตัวบุคคลหรือคู่รายการที่ต้องปรับ** ผ่าน PR ที่มี diff และกรรมการตรวจ

## เกณฑ์การเก็บข้อมูลและทบทวนสิทธิ์

- ไม่เก็บเลขบัตรประชาชน/ที่อยู่/เบอร์โทร/ภาพบุคคล หากไม่จำเป็นต่อการตรวจนักกีฬาลงหลายประเภท
- แยกภาพต้นฉบับ, JSON ที่ถอดได้, รายการรอตรวจ, และผลที่เจ้าหน้าที่รับรอง; บันทึก source page และ revision เพื่อย้อนตรวจ
- ก่อนแชร์โฟลเดอร์ ให้ตรวจสิทธิ์ทุกครั้ง ห้ามตั้ง Anyone/Domain หรือคัดลอกข้อมูลไป Shared Drive ที่มีคนทั่วไปเข้าถึง
- ผู้ดูแลกำหนดวันตรวจทาน/ลบสำเนาภายหลังหมดวัตถุประสงค์ตามนโยบายสถานศึกษา และตรวจว่าข้อมูลส่วนบุคคลไม่ตกค้างใน Git history หรือ CI logs
- ชื่อเดียวกันในคนละโรงเรียน/คนละเพศ/คนละรุ่น **ห้ามรวมตัวตนโดยอัตโนมัติ**
