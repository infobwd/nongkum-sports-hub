# R6 — Mobile Bottom Navigation และการตอบสนองของแท็บ

โครงการ: **มิตรภาพเกม ปี 2569**  
ขอบเขต: UX ของหน้า `index.html` และ `results.html` เท่านั้น; **ไม่เปลี่ยนข้อมูลโปรแกรม 236 รายการหรือผลการแข่งขันที่เผยแพร่ (0 รายการ)**

## วิเคราะห์จากภาพ iPhone

- การ์ดคู่แข่งขันใช้งานได้แล้ว แต่หัวการ์ดซ้ำชื่อกีฬาซึ่งมีหัวกลุ่มกีฬาอยู่ก่อน
- ปุ่มแชร์แบบลูกศรขึ้นขวาดูคล้ายเปิดลิงก์ ไม่ใช่การแชร์
- เมนู `โปรแกรมการแข่งขัน | ผลการแข่งขัน` อยู่ด้านบนหน้าเท่านั้น เลื่อนดูรายการจำนวนมากแล้วต้องเลื่อนกลับเพื่อสลับ
- CSS เดิมให้ลิงก์เมนูบนสูงน้อยกว่า 44px และเป็นลิงก์เปลี่ยนหน้าใหม่ จึงดูเหมือนไม่ตอบสนองในสัญญาณมือถือช้า
- เมื่อเลื่อนใต้แถบสถานะ iPhone อาจเกิดการซ้อนของข้อความกับนาฬิกาหรือสัญญาณโทรศัพท์

## สิ่งที่ปรับ R6

### 1. Bottom Navigation สำหรับมือถือ

- เพิ่มแถบ **ตารางแข่ง | ผลแข่งขัน** ติดหน้าจอด้านล่าง สำหรับความกว้างจอ **ไม่เกิน 690px**
- แสดงแถบเมนูเดิมบน Desktop; บนมือถือซ่อนเมนูซ้ำด้านบนเพื่อให้ทางเลือกชัด
- แต่ละปุ่มสูงอย่างน้อย **56px** มีรูปปฏิทิน/ถ้วยรางวัล แสดงสถานะด้วย `aria-current="page"`
- รองรับ `env(safe-area-inset-bottom)` และเพิ่มพื้นที่ท้ายหน้าให้เลื่อนเห็นการ์ดสุดท้ายได้ ไม่ถูกแถบเมนูบัง
- ลิงก์เป็น `<a href>` ปกติจึงใช้ได้แม้ JavaScript ยังไม่ทำงาน ไม่รอ fetch ก่อนเริ่มเปลี่ยนหน้า
- `js/navigation.js` ให้การตอบสนองทันทีจาก `pointerdown`/CSS active และสถานะ `กำลังเปิด...` เมื่อกดสลับ
- เมื่อกดแท็บปัจจุบันจะเลื่อนกลับด้านบนโดยไม่โหลดหน้าใหม่
- กรณีกลับมาจาก Browser Back/Forward Cache จะล้างสถานะกำลังเปิดทันทีด้วย `pageshow`

### 2. ตัวกรองข้ามหน้า

- `js/navigation.js` สร้างลิงก์เริ่มต้นจาก `school`, `sport`, `level` ใน URL และโรงเรียนที่เคยเลือก
- หน้าโปรแกรมและหน้าผลเรียก `NongkumNavigation.update(state)` ทุกครั้งเมื่อค่าตัวกรองเปลี่ยน
- เมื่อมี `?fixture=` หรือ `?result=` (ลิงก์แชร์ตรงรายการ) จะไม่เอาค่าโรงเรียนเก่าจากเครื่องผู้รับมาปิดบังรายการนั้น
- ไม่สร้าง endpoint ใหม่ ไม่ใช้ Service Worker และไม่เปลี่ยนกรอบอนุมัติข้อมูล/ข้อมูล Google Sheets
- เนื่องจากเป็นเว็บสองหน้าแบบ GitHub Pages จึงยังเป็นการโหลด HTML/JSON เมื่อเปลี่ยนหน้า แต่ **ไม่ต้องรอให้โหลดก่อนรับการแตะ**

### 3. การ์ดและ iPhone

- ใช้ SVG แบบฝังสำหรับไอคอนแชร์แทนตัวอักษร `↗` โดยไม่เรียกไฟล์ภาพภายนอก
- บนการ์ดโปรแกรม แสดงสัญลักษณ์กีฬา + รุ่นอายุ แทนการซ้ำชื่อกีฬาเต็มใต้หัวกลุ่มเดียวกัน
- คงชื่อกีฬาครบใน `aria-label` ของสัญลักษณ์ และในหัวกลุ่มกีฬา
- ปุ่มแชร์ยังเป็น 44×44px พร้อม `aria-label`, แบ่งจากเลขคู่/เลขรายการ
- เพิ่มตัวบังบริเวณแถบสถานะ iOS เมื่อผู้ใช้ **เลื่อนหน้าแล้วเท่านั้น** (ไม่มีตัวบัง 44px ตอนเปิดหน้าแรก) เพื่อหลีกเลี่ยงการตัดโลโก้ตอนเริ่มต้น
- ส่วนหัวบน Desktop ยังใช้ได้ตามเดิม; ไม่เปลี่ยนหน้าผลการแข่งขันเป็น Single Page Application

## ตรวจรับบนเครื่องจริง (ยังต้องทำ)

- [ ] iPhone Safari: เลื่อนลงอย่างน้อย 20 การ์ด แล้วแตะผลแข่งขันด้านล่าง **ครั้งเดียว** ต้องเริ่มเปิดหน้าใหม่
- [ ] iPhone Safari: แตะกลับตารางแข่ง โรงเรียนและกีฬาที่เลือกยังอยู่
- [ ] iPhone Safari: เลื่อนถึงท้ายหน้า ไม่มีการ์ดหรือปุ่มอ่านรายละเอียดถูกเมนูล่างบัง
- [ ] iPhone Safari: เมื่อเลื่อนขึ้นลง เนื้อหาด้านบนไม่ทับเวลาและไอคอนสถานะ; หน้าแรกโลโก้ไม่ถูกบัง
- [ ] iPhone เพิ่มเป็นหน้าจอ Home Screen: Bottom Safe Area ไม่ทับ Home Indicator
- [ ] Android Chrome จอ 320–430px: เมนูไม่ล้น ทั้งสองแท็บกดได้และ focus ด้วยคีย์บอร์ดได้
- [ ] เปิดลิงก์แชร์คู่แข่งขัน/ผลรายการ: ไม่ถูกค่าโรงเรียนที่เคยเลือกในเครื่องรับกรองทิ้ง
- [ ] บน Desktop ยังคงเมนูด้านบน และไม่มี Bottom Navigation เพิ่ม
- [ ] ไม่มีผลร่างหรือคะแนนสมมติปรากฏบนหน้าผลรับรอง

**การผ่าน CI ไม่ใช่ผลทดสอบ Safari จริง**; ใช้ภาพ iPhone หลัง GitHub Pages Deploy ประกอบการตรวจรับก่อนปิด R6
