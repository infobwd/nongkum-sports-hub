# R15-D — คู่มือรับภาพใบบันทึกผลสู่ผลรับรอง (สนามแข่งขัน)

วันที่ 5 พ.ย. 2569 · เจ้าของงาน: R15-D · ฐานอ้างอิง: \`R15_RESULTS_STANDINGS_PHOTO_JSON_PLAN.md\`, \`RESULTS_IMPLEMENTATION_R1_R3.md\`, \`forms/score-sheet.html\` และ R5 QA

> เอกสารนี้เป็น **คู่มือปฏิบัติงานพร้อมซ้อมด้วยข้อมูลสมมติ** ไม่ใช่หลักฐานว่าได้รับผลจริง ไม่ติดตั้ง Google Apps Script และไม่อนุมัติ/เผยแพร่ผลอัตโนมัติ การตรวจรับเครื่องจริงและกติกาคะแนนอยู่ใน gate อื่น

## 1. บทบาทและเส้นทาง (manual-first)

| บทบาท | ทำอะไร | ห้ามทำ |
|---|---|---|
| กรรมการสนาม | บันทึกผลจริง ลงวันที่/เวลาและเซ็นใบ A4 ส่งใบครบหน้า | แจ้งคะแนนปากเปล่าแทนใบที่มีหลักฐาน |
| เจ้าหน้าที่ถ่าย/รับภาพ | ตรวจคุณภาพภาพ ชี้รหัสคู่ และส่งเข้าพื้นที่ส่วนตัว | อัปโหลดรูปลง public repository, LINE กลุ่มสาธารณะ หรือ issue/PR |
| ผู้ถอดผล | อ่านผลสองรอบ เทียบทีม A/B และรหัสกับทะเบียน บันทึก draft ส่วนตัว | เดาคะแนนหรือแก้ใบต้นฉบับ |
| ผู้ตรวจทาน | เทียบภาพกับ draft อิสระ ตรวจคะแนน/กีฬา/รอบ/จำนวนชุด และแจ้งข้อขัดแย้ง | รับรองแทนผู้มีอำนาจ |
| ผู้รับรองที่ได้รับมอบหมาย | ตรวจใบลงนาม เห็นผลการตรวจ และลง approval พร้อมเวลาและ revision ในทะเบียนส่วนตัว | รับรองภาพอ่านไม่ชัดหรือคู่ที่ไม่ยืนยัน |
| ผู้ดูแลเผยแพร่ | export candidate approved-only → R15-C validator → PR/diff/CI → เผยแพร่หลังตรวจรับ | ใส่ข้อมูล pending/review ลง \`data/public-results.json\` |

หากคนมีจำกัดต้องบันทึกการควบหน้าที่และให้ผู้รับรองทวนภาพกับข้อมูลต้นฉบับอย่างอิสระ การถอดโดย AI เป็นเพียงคำแนะนำให้ผู้ตรวจแก้ ไม่ถือเป็นหลักฐานการรับรอง

## 2. เส้นทางสถานะ/จุดหยุด

\`\`\`text
รับใบลงนาม → รับภาพในพื้นที่ปิด [received]
  ├─ มุมขาด/แสงสะท้อน/ตัวเลขไม่อ่านออก → [recapture_required] → ขอภาพใหม่หรือดูใบจริง
  └─ ภาพครบ → [transcribed] (ร่างส่วนตัว) → [crosschecked]
       ├─ fixture ไม่ตรง/ไม่มีทีม/ผลขัดแย้ง → [hold] ส่งกลับกรรมการเพื่อชี้แจง
       └─ หลักฐานครบ → [pending_approval] → ผู้มีอำนาจลงนาม [approved]
            → export candidate (ไม่ใช่ public) → R15-C gate + PR/CI
            → reviewer อนุมัติ diff → merge → ตรวจบนเว็บ [published]
\`\`\`

ก่อนกดอนุมัติต้องมี **ใบต้นฉบับ+ลายเซ็น+fixture ID ที่ผูกได้**. ห้ามใช้สถานะ approved เพียงเพราะ AI อ่านคะแนนได้หรือเพียงเพราะอยู่ใน Sheets. ผลแก้ไขหลังเผยแพร่ต้องเพิ่ม revision และ correction note/หลักฐานยืนยัน ไม่เขียนทับเงียบ ๆ

## 3. วิธีถ่ายด้วยมือถือสำหรับเจ้าหน้าที่สนาม

1. เปิดจากหน้าโปรแกรม **คู่แข่งขัน/รายการกรีฑาที่ตรงจริง** → ปุ่มใบบันทึกผล เพื่อให้แบบ A4 เติม fixture ID อัตโนมัติ; หากใช้แบบเปล่า ให้เขียนรหัสจากทะเบียนบนกระดาษและให้ผู้ตรวจทานยืนยัน. รหัสที่เขียนจากความจำ **ไม่เพียงพอ**.
2. หลังกรรมการเซ็นแล้ว วางกระดาษ A4 บนพื้นเรียบไม่สะท้อน แสงสว่างสม่ำเสมอ ถ่ายแนวตั้งจากด้านบนให้ **4 มุมครบ** ไม่ตัดหัวข้อรหัส ผลคะแนน หรือแถวลายเซ็น; ห้ามใช้ฟิลเตอร์หรือสแกนที่ลบลายมือ.
3. ซูมตรวจที่หน้าจอมือถือ 100% ว่ารหัสคู่/ชนิดกีฬา/โรงเรียน A-B/คะแนนทุกช่วง/ผู้ชนะ/วันที่/ลายเซ็นทั้ง 3 ช่องอ่านได้. ถ้าฟอร์มมีด้านหลังหรือบันทึกต่อ ให้ถ่ายทุกหน้าเรียงกัน.
4. ถ้าภาพสั่น เบลอ เงาทับตัวเลข แสงสะท้อน ขาดมุม หรือคำตอบแก้ด้วยลบคำ: **อย่าเดา**. ถ่ายใหม่ทันทีโดยวางนิ่ง แตะโฟกัส ปรับมุมแสง ลดเงา; ตรวจตัวเลขเดิมกับกรรมการ. หากไม่มีใบแล้วให้แจ้งผู้ตรวจและพักสถานะ \`recapture_required\`.
5. ส่งภาพแบบ original/ไฟล์เพื่อคงรายละเอียดผ่านช่องทาง **ส่วนตัวที่ผู้จัดอนุญาต** ไปยังโฟลเดอร์ปิด ไม่แชร์ URL ที่ทุกคนเปิดได้; ตั้งชื่อภายในเช่น \`25691112_TESTONLY\` สำหรับซ้อม หรือใช้ทะเบียนลำดับรับของงานจริงโดยไม่มีชื่อเด็ก/ข้อมูลส่วนตัวใน filename.
6. เจ้าหน้าที่ตอบกลับว่าได้รับภาพครบ, ระบุเลขที่รับเรื่องภายใน, จำนวนภาพ, เวลาไทย และแจ้งกรณีต้องถ่ายใหม่. มือถือออฟไลน์ให้เก็บไว้ในพื้นที่ปลอดภัยแล้วส่งเมื่อมีเน็ต ห้ามยืนยันว่าอัปโหลดสำเร็จจากการกดส่งอย่างเดียว.

**การถ่ายใหม่:** เก็บภาพเดิมไว้ในหลักฐานส่วนตัวพร้อม mark \`superseded\` และลำดับใหม่; ใช้ภาพที่อ่านชัดที่สุดเป็น primary. ลายเซ็น/เลขโทรศัพท์/ภาพนักเรียน/ลิงก์ Drive ไม่อยู่ใน JSON สาธารณะ

## 4. ตรวจ A4 กับ fixture registry ก่อนรับผล

ข้อมูลจาก \`forms/score-sheet.js\` ล็อก \`fixtureId\`, \`sportName\`, division, round, sourcePage, sourceTime, teamA/B เมื่อเปิด \`?fixture=<id>\` และป้องกันพิมพ์เมื่อต้นทางไม่ตรง (R5). ฟอร์มเปล่ายอมให้พิมพ์โดย **ไม่เติม ID** เพื่อกรอกบนกระดาษเอง ดังนั้นไม่สามารถถือว่าแบบทุกใบผูก ID ถูกต้องอัตโนมัติได้

รายการอ้างอิงปัจจุบัน \`data/program-from-pdf-2569-20261104-draft.json\`: 237 ID (match 187, track_event 50). ไฟล์ยังมี \`metadata.all_data_approved=false\`; เป็นทะเบียนอ้างอิงที่ต้องตรวจรับรายการแข่งขันจริง ไม่ใช่การอนุมัติผลคะแนน. ไม่ใช้ \`data/draft-schedule.json\` ชุดเก่า 236 รายการในการผูกผลใหม่

| สิ่งตรวจบนใบ A4 | วิธีเทียบ / เงื่อนไขหยุด |
|---|---|
| fixture/event ID | มีใน registry ล่าสุดเพียง 1 รายการ; ชนิด \`match\` หรือ \`track_event\` ต้องตรงแบบ |
| กีฬา / รุ่น / รอบ / เลขคู่ / หน้า PDF | ตรงกับทะเบียนและใบที่ใช้จริง; รอบ/คู่ที่ยังเป็น placeholder ต้องได้คำยืนยัน ไม่เดาจากลำดับ |
| ทีม A/B | ลำดับฝั่งต้องตรง registry; หากทีมยังเป็น "อันดับ 1" หรือไม่ทราบชื่อ ให้ **hold** จนทีมจริงยืนยัน |
| กรีฑา | event ID, ชื่อรายการ, ลู่และโรงเรียนตรง; \`lanes[].school_id\` ที่เป็น null ต้องยืนยันการ map โรงเรียน/ศูนย์ก่อน export; ชื่อผู้แข่งขันไม่เผยแพร่ |
| วันที่/เวลา/สนาม | ระบุเวลาที่แข่งขันจริง ไม่คัดลอกเวลาสูจิบัตรที่ยังรอยืนยัน; ไม่ใช้เวลาคาดเดาเป็นหลักฐาน |
| ผลและลายเซ็น | คะแนนครบตามโหมดกีฬา, ผู้ชนะ/เสมอ/ตัดสิน, หมายเหตุประท้วง และผู้บันทึก/ตรวจ/รับรองมีการลงนาม |

แบบฟอร์มมีช่องลงนามครบ **แต่ยังไม่มีหลักฐานการพิมพ์ 1 หน้า A4 ทุกประเภทบน Safari/Chrome และเครื่องพิมพ์จริง**. ต้องทดสอบใบฟุตบอล เปตอง กีฬาเซ็ต ยิงจุดโทษ ชักเย่อ กรีฑา อย่างน้อยก่อนแจกกรรมการ

## 5. ตรวจเทียบสองรอบและหลักฐานรับรอง

- รอบ 1 ผู้ถอดอ่าน *ต้นฉบับภาพ*, กรอก candidate ส่วนตัว โดยบันทึกความไม่ชัดใน \`uncertain_fields\`; ช่องไม่ชัดต้องเว้นว่าง, ห้ามใส่ 0 แทน
- รอบ 2 ผู้ตรวจทวน *ภาพ* แยกจากข้อมูลที่กรอก แล้วเทียบทีละช่อง: fixture, sport, division, team order, scores/sets/ranking, ties/penalty, winner, signer and signatures
- คู่คะแนนที่เสมอ แต่ใบมี penalty shootout หรือตัดสินพิเศษ ห้ามสรุป winner ด้วยการดู score รวมเพียงอย่างเดียว; ให้ R15-B/C ระบุ representation ที่รองรับ
- score/sets, ฟุตบอลได้-เสีย, เปตอง และกติกาแยก phase: ให้ validator ของ R15-C และ rules R15-B เป็นตัวชี้ขาด; ถ้าไม่มี rule ที่รับรองให้หยุดไม่สร้าง standings
- บันทึก \`evidence_id\` แบบส่วนตัว, checksum ภาพถ้ามี, ผู้ถอด, ผู้ตรวจ, เวลาไทย, ผู้อนุมัติ, \`approved_at\`, \`revision\`, \`correction_note\` ใน private audit; ตรวจว่าลายเซ็นบนใบสัมพันธ์กับผู้ได้รับมอบหมาย

## 6. Export/PR/การแก้ไขย้อนหลัง

1. เลือกเฉพาะ candidate ที่ \`approved\` โดยผู้รับรองมีสิทธิ์ พร้อม audit ครบ; ปฏิเสธ repeated \`result_id\` และผลซ้ำใน \`fixture_id\` หรือ \`event_id\` โดยไม่มี revision policy.
2. แปลงเป็น public schema v1 **โดยตัด** evidence link, ชื่อผู้ลงนาม/อีเมล/ลายเซ็นและข้อมูลผู้แข่งขัน; รักษา ID, sport, division, teams, score/sets/winner/ranking ที่รองรับ. เก็บ private-to-public mapping เฉพาะพื้นที่ปิด.
3. R15-C เป็น **ผู้รับผิดชอบการตรวจจริง**: duplicate, fixture/team mismatch, rule contradiction, approval proof, correction revision และ snapshot. ถ้า validator ยังไม่พร้อมให้ค้าง candidate ไม่ปล่อยผลขึ้น public.
4. เปิด PR เฉพาะผลรับรองจริงพร้อมผลตรวจและผู้ตรวจ PR; เปรียบเทียบ diff กับ public เดิม, ไม่ลบผลเก่าเงียบ ๆ, ไม่ผูก workflow ให้ autopublish ผลทันทีจากภาพ.
5. หลัง merge ตรวจว่า GitHub Pages เผยแพร่ JSON รุ่นใหม่แล้ว; กดรีเฟรชหน้า \`results.html\` และ \`standings.html\`; ถ้าข้อมูลไม่ตรงให้หยุดประกาศผลและตรวจ revision/แคช.
